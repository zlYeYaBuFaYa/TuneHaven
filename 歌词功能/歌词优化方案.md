# 歌词功能优化方案

> 支持歌词导入、在线歌词搜索、搜索歌词本地保存

---

## 一、需求概述

### 1.1 当前现状

| 能力 | 状态 |
|------|------|
| 内嵌歌词读取（ID3 标签） | ✅ 已支持 |
| 本地 LRC 文件读取 | ✅ 已支持（Documents/Lyrics/） |
| LRC 格式解析（时间轴同步） | ✅ 已支持 |
| 纯文本歌词展示 | ✅ 已支持 |
| 手动导入 LRC 文件 | ❌ 无 UI 入口 |
| 在线歌词搜索 | ❌ 不支持 |
| 歌词自动匹配 | ❌ 不支持 |
| 歌词删除/更新 | ❌ 不支持 |

### 1.2 目标

1. **歌词导入**：用户可通过系统文件选择器导入 LRC 文件并关联到指定歌曲
2. **在线歌词搜索**：接入 LRCLIB 免费 API，支持自动匹配和手动搜索
3. **歌词本地保存**：在线搜索到的歌词保存到本地，后续免网络加载
4. **歌词管理**：已有歌词的歌曲可手动更新或删除歌词

## 二、歌词加载优先级（修改后）

采用 **fallthrough 回退链**策略：每一步成功即返回，失败则继续下一步。

```
LyricsService.loadLyrics(for song:) 
  │
  ├─ 1. 优先按数据库指定来源加载（song.lyricsSource 非 nil 时）
  │     ├─ .embedded → 读取 ID3 内嵌歌词 → 成功则返回
  │     └─ .file / .manual → 读取 song.lyricsPath 指向的 LRC 文件 → 成功则返回
  │     └─ ⚠️ 失败（文件丢失/损坏等）→ fallthrough 到步骤 2
  │
  ├─ 2. 回退：尝试读取内嵌歌词（ID3 unsynchronizedLyric）→ 成功则返回
  │
  ├─ 3. 回退：尝试读取外部 LRC 文件
  │     ├─ 先尝试 Documents/Lyrics/{songId}.lrc
  │     └─ 再尝试 Documents/Lyrics/{歌曲标题}.lrc（兼容旧数据）
  │     └─ 成功则返回
  │
  ├─ 4. [新增] 在线自动匹配（需同时满足以下条件）
  │     ├─ auto_match_lyrics 开关已开启
  │     ├─ 该歌曲未在匹配冷却期内（见"匹配冷却机制"）
  │     └─ LRCLIB /api/get 精确匹配（title + artist + album + duration）
  │         ├─ 匹配成功且非纯器乐曲
  │         │   ├─ 清理可能存在的旧 {歌曲标题}.lrc 文件（避免孤儿文件）
  │         │   ├─ 保存到 Documents/Lyrics/{songId}.lrc
  │         │   └─ 更新数据库 lyricsPath + lyricsSource = .file → 返回
  │         ├─ 匹配成功但 instrumental == true → 标记冷却 → 返回 nil
  │         └─ 匹配失败（404）→ 标记冷却 → 返回 nil
  │
  └─ 5. 都没有 → 返回 nil → 播放器显示封面图 + "搜索歌词"按钮
```

## 三、技术方案

### 3.1 在线歌词 API：LRCLIB

| 项目 | 说明 |
|------|------|
| 官网 | https://lrclib.net |
| 费用 | 完全免费 |
| API Key | 不需要 |
| 速率限制 | 无 |
| 返回格式 | JSON |
| 歌词格式 | LRC（syncedLyrics）+ 纯文本（plainLyrics） |

**核心接口：**

#### 精确匹配（自动搜索用）

```
GET https://lrclib.net/api/get
  ?track_name=xxx
  &artist_name=xxx
  &album_name=xxx
  &duration=233
```

根据歌曲签名精确匹配，duration 允许 ±2 秒误差。返回单条结果或 404。

#### 关键词搜索（手动搜索用）

```
GET https://lrclib.net/api/search
  ?track_name=xxx
  &artist_name=xxx
```

模糊搜索，返回最多 20 条结果数组。

#### 响应示例

```json
{
  "id": 3396226,
  "trackName": "I Want to Live",
  "artistName": "Borislav Slavov",
  "albumName": "Baldur's Gate 3 (Original Game Soundtrack)",
  "duration": 233,
  "instrumental": false,
  "plainLyrics": "I feel your breath upon my neck\n...",
  "syncedLyrics": "[00:17.12] I feel your breath upon my neck\n[00:21.28] ..."
}
```

`syncedLyrics` 即标准 LRC 格式，可直接传给现有 `LyricsService.parseLRC()` 解析。

### 3.2 请求要求

- Header: `User-Agent: TuneHaven/1.0 (iOS Music Player)`
- 编码: URL 参数需 URL Encode
- 超时: 建议 10 秒

## 五、数据模型

### 5.1 LRCLibTrack（新增）

```swift
struct LRCLibTrack: Codable, Identifiable {
    let id: Int
    let trackName: String
    let artistName: String
    let albumName: String
    let duration: Double
    let instrumental: Bool
    let plainLyrics: String?
    let syncedLyrics: String?
}
```

### 5.2 LRCLibTrack 辅助属性

```swift
extension LRCLibTrack {
    /// 是否有时间轴同步歌词
    var hasSyncedLyrics: Bool { syncedLyrics != nil && !syncedLyrics!.isEmpty }

    /// 是否有任何歌词（同步或纯文本）
    var hasAnyLyrics: Bool { hasSyncedLyrics || (plainLyrics != nil && !plainLyrics!.isEmpty) }

    /// 优先返回同步歌词，无则返回纯文本
    var bestLyrics: String? { syncedLyrics ?? plainLyrics }

    /// 格式化时长显示（如 "3:39"）
    var durationText: String {
        let mins = Int(duration) / 60
        let secs = Int(duration) % 60
        return "\(mins):\(String(format: "%02d", secs))"
    }
}
```

### 5.3 现有模型（无需改动）

- `Song.lyricsPath: String?` — 歌词文件相对路径
- `Song.lyricsSource: LyricsSource?` — 歌词来源（.embedded / .file / .manual）
- `LyricsData` — 歌词加载结果
- `LyricsLine` — 单行歌词（时间戳 + 文本）

### 5.4 纯文本歌词与器乐曲处理策略

| 场景 | 处理方式 |
|------|---------|
| `syncedLyrics` 非空 | 作为 LRC 解析，走时间轴同步展示 |
| 仅有 `plainLyrics` | 保存为 `.lrc` 文件（无时间轴标签），加载时走纯文本回退展示（见下方适配说明） |
| `instrumental == true` | **自动匹配**：跳过，标记冷却；**手动搜索**：结果列表中标注"🎵 器乐曲（无歌词）"，不显示"使用此歌词"按钮 |
| `plainLyrics` 和 `syncedLyrics` 均为空 | 结果列表中标注"无可用歌词"，禁用选择 |

#### 纯文本歌词完整链路适配（需改动 2 处现有代码）

当前代码中，`loadEmbedded` 有纯文本回退逻辑（`lines` 为空时将文本按行拆分生成伪时间轴），但 `loadFromFile` 没有。同时 PlayerView / LyricsView 仅在 `lines` 非空时展示歌词。

**适配点 1 — `LyricsService.loadFromFile`**：增加与 `loadEmbedded` 相同的纯文本回退逻辑：

```swift
private func loadFromFile(relativePath: String) -> LyricsData? {
    let url = SandboxPathManager.lyricsFileURL(relativePath: relativePath)
    guard let content = try? String(contentsOf: url, encoding: .utf8) else { return nil }
    let lines = parseLRC(content)
    if lines.isEmpty && !content.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty {
        let plainLines = content.components(separatedBy: "\n")
            .filter { !$0.trimmingCharacters(in: .whitespaces).isEmpty }
            .enumerated()
            .map { LyricsLine(timestamp: Double($0.offset) * 3, text: $0.element) }
        return LyricsData(source: .file, lines: plainLines, rawText: content)
    }
    return LyricsData(source: .file, lines: lines, rawText: content)
}
```

**适配点 2 — `LyricsView`**：增加 `lines` 为空但 `rawText` 非空时的纯文本展示分支（滚动文本，不跟随播放进度）：

```swift
var body: some View {
    if !lyricsData.lines.isEmpty {
        // 现有时间轴同步歌词展示逻辑
    } else if !lyricsData.rawText.isEmpty {
        ScrollView(.vertical, showsIndicators: false) {
            Text(lyricsData.rawText)
                .font(.subheadline)
                .foregroundColor(palette.playerSubtext)
                .multilineTextAlignment(.center)
                .padding()
        }
    }
}
```

> **说明**：适配点 1 使用伪时间轴方案（每行间隔 3 秒），与现有 `loadEmbedded` 逻辑一致，可复用 LyricsView 的时间轴展示。如采用此方案，适配点 2 可作为兜底备选。两种方案择一即可。

## 六、核心 API 设计

### 6.1 LRCLibAPIClient

采用**协议 + 实现类**模式，便于单元测试时注入 Mock。

```swift
/// 协议定义（便于测试 Mock）
protocol LRCLibAPIClientProtocol {
    /// 精确匹配（自动搜索）
    /// - Parameter duration: 歌曲时长（秒），LRCLIB 接受整数秒，调用方需将 TimeInterval 转为 Int
    func get(
        trackName: String,
        artistName: String,
        albumName: String,
        duration: Int
    ) async throws -> LRCLibTrack?

    /// 关键词搜索（手动搜索，返回最多 20 条）
    func search(
        trackName: String,
        artistName: String?
    ) async throws -> [LRCLibTrack]
}

/// 实现类
final class LRCLibAPIClient: LRCLibAPIClientProtocol {
    private let baseURL = "https://lrclib.net/api"
    private let userAgent = "TuneHaven/1.0 (iOS Music Player)"
    private let session: URLSession
    private let timeout: TimeInterval = 10

    init(session: URLSession = .shared) {
        self.session = session
    }

    func get(trackName:artistName:albumName:duration:) async throws -> LRCLibTrack? { ... }
    func search(trackName:artistName:) async throws -> [LRCLibTrack] { ... }
}
```

> **duration 类型说明**：`Song.duration` 为 `TimeInterval`（Double），调用 API 时需转换为 `Int(song.duration)`。LRCLIB 精确匹配允许 ±2 秒误差，截断精度不影响匹配。

### 6.2 LyricsService 新增方法

```swift
extension LyricsService {
    /// 在线精确匹配（自动模式，静默调用）
    func autoMatchOnline(for song: Song) async -> LyricsData?

    func searchOnline(title: String, artist: String?) async -> [LRCLibTrack]

    /// 将 LRC 内容保存到本地文件 + 更新数据库

    /// 从系统文件选择器导入 LRC 文件
    func importLyricsFile(url: URL, for songId: UUID) async throws
```

### 7.5 歌词变更后的刷新机制

当前 PlayerView 仅在**切歌**（`onChange(of: currentSong?.id)`）和**首次进入**（`.task`）时加载歌词。歌词保存/删除/导入后 PlayerView 不会自动感知变化，需要主动触发刷新。

**方案：通过 sheet dismiss 回调触发重新加载**

```swift
// PlayerView 中
.sheet(item: $activeLyricsSheet) { sheet in
    switch sheet {
    case .search:
        LyricsSearchView(song: song, onSaved: {
            Task { await loadLyrics() }
        })
    }
}

// 导入歌词成功后
.fileImporter(...) { result in
    // ... importLyricsFile 成功后
    Task { await loadLyrics() }
}

// 删除歌词成功后
// deleteLyrics 完成 → 直接设置 lyricsData = nil
```

**各场景刷新方式汇总：**

| 场景 | 刷新方式 |
|------|---------|
| 手动搜索保存成功 | LyricsSearchView 通过 `onSaved` 闭包通知 PlayerView → 重新 `loadLyrics()` |
| 手动导入成功 | `.fileImporter` 回调中直接 `loadLyrics()` |
| 删除歌词成功 | 直接设置 `lyricsData = nil` |
| 自动匹配成功 | 在 `loadLyrics()` 流程内完成，无需额外刷新 |
| 从 SongInfoEditView 操作 | 返回 PlayerView 时通过 `.onAppear` 或 `onChange` 判断是否需要重新加载 |

## 八、核心流程

### 8.1 自动匹配流程

```
播放歌曲 → loadLyrics(for: song)
  → 本地无歌词（步骤 1–3 均未命中）
  → 检查 auto_match_lyrics == true
  → 检查冷却记录：lyrics_match_cooldown[songId] 是否在 7 天内
      → 在冷却期内 → 跳过，返回 nil
  → LRCLibAPIClient.get(trackName, artistName, albumName, Int(duration))
  → 请求成功：
      → instrumental == true → 标记冷却 → 返回 nil
      → syncedLyrics 非空：
          → 检查并清理旧的 {歌曲标题}.lrc 文件（如存在）
          → saveLyrics(syncedLyrics, for: songId)
              → 写入 Documents/Lyrics/{songId}.lrc
              → 更新数据库 lyricsPath = "{songId}.lrc", lyricsSource = .file
          → parseLRC() → 返回 LyricsData
      → syncedLyrics 为空但 plainLyrics 非空：
          → 同上流程保存 plainLyrics（后续加载走纯文本展示）
  → 请求失败（404/网络错误）→ 标记冷却 → 返回 nil
```

### 8.2 手动搜索流程

```
用户点击"搜索歌词" → 弹出 LyricsSearchView（不受冷却限制）
  → 预填歌名 + 艺术家
  → 用户可编辑关键词 → 点击搜索（歌名必填）
  → 调用 LRCLibAPIClient.search(trackName, artistName)
  → 请求成功：
      → 结果为空 → 显示"未找到匹配歌词，请尝试修改关键词"
      → 有结果 → 展示结果列表（区分时间轴歌词/纯文本/器乐曲）
  → 请求失败 → 显示错误 + 重试按钮
  → 用户点击某行 → 展开歌词预览（最多 6 行）
  → 点击"使用此歌词"
      → 检查并清理旧的 {歌曲标题}.lrc 文件（如存在）
      → saveLyrics(track.bestLyrics, for: songId)
      → 清除该 songId 的冷却记录
      → dismiss
      → PlayerView 自动刷新歌词
```

### 8.3 手动导入流程

```
用户点击"导入歌词" → .fileImporter(allowedContentTypes: [.plainText])
  → 选择 .lrc 文件
  → importLyricsFile(url, for: songId)
      → startAccessingSecurityScopedResource()
      → 读取文件内容
      → 校验内容非空
      → 检查并清理旧的 {歌曲标题}.lrc 文件（如存在）
      → 写入 Documents/Lyrics/{songId}.lrc
      → 更新数据库 lyricsPath + lyricsSource = .file
      → 清除该 songId 的冷却记录
      → stopAccessingSecurityScopedResource()
  → 导入失败 → Snackbar 提示（LYR003）
  → 导入成功 → PlayerView 自动刷新歌词
```

### 8.4 删除歌词流程

```
用户点击"删除歌词" → 确认弹窗
  → deleteLyrics(for: songId)
      → 删除 Documents/Lyrics/{songId}.lrc
      → 清除数据库 lyricsPath = nil, lyricsSource = nil
  → PlayerView 刷新 → 显示封面图
```

## 十一、UserDefaults 新增

| Key | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `auto_match_lyrics` | Bool | true | 自动匹配在线歌词开关 |
| `lyrics_match_cooldown` | [String: Double] | [:] | 自动匹配冷却记录（songId → 上次尝试的 `timeIntervalSince1970`） |

### 匹配冷却机制

自动匹配失败（404 或 instrumental）后，将 `songId` 记入冷却字典，**7 天内不再对该歌曲发起自动匹配请求**，避免每次播放都发起无意义的网络请求。

- 冷却期到期后自动失效，下次播放时重新尝试
- 用户手动点击"搜索歌词"不受冷却限制
- 冷却记录在用户手动搜索并成功保存歌词后自动清除

> **序列化说明**：UserDefaults 不支持直接存储 `[String: Date]`。实际存储为 `[String: Double]`，value 为 `Date().timeIntervalSince1970`。读取时通过 `Date(timeIntervalSince1970:)` 还原，判断是否超过 7 天（`604800` 秒）。

## 十二、注意事项

1. **网络请求仅在需要时发起**：本地有歌词则不请求网络
2. **保存后即本地化**：在线获取的歌词保存到文件后，后续播放不再请求网络
3. **不修改音频文件**：歌词保存为独立 LRC 文件，不写入 ID3 标签
4. **超时处理**：在线请求设置 10 秒超时，避免阻塞播放体验
5. **主题适配**：所有新增 UI 通过 `palette` 获取颜色，适配主题系统
6. **兼容旧数据**：加载优先级步骤 3 中同时兼容 `{songId}.lrc` 和旧的 `{title}.lrc` 命名方式
7. **旧文件清理**：保存新歌词（自动匹配/手动搜索/导入）时，若发现同一首歌存在旧的 `{title}.lrc` 文件，自动删除旧文件避免冗余
8. **冷却机制**：自动匹配失败后 7 天内不重复请求同一首歌，避免无效网络开销；手动搜索和导入不受此限制
9. **纯文本歌词兼容**：无时间轴标签的歌词保存后，以滚动纯文本模式展示（使用 `rawText`），不走时间轴同步逻辑
10. **Info.plist**：项目已有网络权限配置（`App Transport Security`），无需额外改动
11. **已知限制 — `LyricsSource.embedded` 映射**：CoreData 中 `lyricsSource` 默认值为 `0`，与 `LyricsSource.embedded`（rawValue = 0）相同。`SongMapper` 当前以 `!= 0` 判断 nil，导致无法显式存储 `.embedded` 来源。本次优化主要操作 `.file` 来源（rawValue = 1），不受此影响。后续若需修复，可将 CoreData 默认值改为 `-1` 表示未设置
