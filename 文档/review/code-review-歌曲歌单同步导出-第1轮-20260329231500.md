## 问题列表

### A. 正确性与安全

#### 1. [🟡] SyncImportService — 歌曲 replace 逻辑未真正实现

- **文件**：`Domain/Services/SyncImportService.swift` L141-170
- **描述**：歌曲冲突解析为 `.replace` 时，代码直接调用 `processWiFiFile`，但该方法基于 SHA256 哈希去重。相同哈希的文件返回 `.skippedDuplicate` → 跳过；不同哈希的文件会作为新歌曲导入 → 不会删除旧版本。两种情况都不是用户期望的「替换」行为。
- **修复**：`.replace` 场景下，先删除匹配的旧歌曲再导入新版本；同哈希时视为已存在无需替换（计入 imported 而非 skipped）。

#### 2. [🟡] SyncImportService — saveAsCopy 分支死代码

- **文件**：`Domain/Services/SyncImportService.swift` L161-166
- **描述**：`.skippedDuplicate` 处理中 `if resolution == .saveAsCopy` 的两个分支代码完全相同（都执行 `songsSkipped += 1`），属于无意义分支。
- **修复**：合并分支，统一处理。

#### 3. [🟡] importCover / importLyrics — 目标文件已存在时静默失败

- **文件**：`Domain/Services/SyncImportService.swift` L388-391, L399-401
- **描述**：`FileManager.copyItem` 在目标文件已存在时抛 `NSFileWriteFileExistsError`，`try?` 吞掉错误导致 replace 场景下封面/歌词无法更新。
- **修复**：copy 前先 `removeItem` 清理已有文件。

#### 4. [🟡] TuneHavenPackager.writePackage — 源文件截断时无限循环风险

- **文件**：`Core/Storage/TuneHavenPackager.swift` L376-382
- **描述**：如果源文件在获取 `fileSize` 后被截断，`readData` 返回空 Data，`remaining -= 0` 导致循环永不退出。
- **修复**：检测空读取及时 break。

### B. 质量与规范

#### 5. [🟡] SyncImportService — Domain 层直接引用 Core 层 SandboxPathManager

- **文件**：`Domain/Services/SyncImportService.swift` L388, L400
- **描述**：Domain 层 `SyncImportService` 直接引用 `Core/Storage/SandboxPathManager`，违反 Clean Architecture 单向依赖规则。项目内其他 Domain 服务通过 `FileStorageProviding` 等协议解耦。
- **修复**：通过 `FileStorageProviding` 协议的路径属性获取目标目录，注入替代直接引用。

#### 6. [🟡] TuneHavenPackager.export — 歌单 groupName 始终为 nil

- **文件**：`Core/Storage/TuneHavenPackager.swift` L140
- **描述**：`PlaylistExportData.groupName` 始终传 nil，歌单分组信息丢失。设计方案明确要求导出分组名称以便跨设备恢复。
- **修复**：`SyncPackaging` 协议增加 `groupNames` 映射参数，`SyncExportService` 加载分组信息后传入。
