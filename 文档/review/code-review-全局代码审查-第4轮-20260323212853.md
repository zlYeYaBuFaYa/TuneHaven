- **文件**：`Domain/Services/MusicLibraryService.swift`，第 132-146 行

#### 🟡-NEW-02 LyricsService 中 UserDefaults 直接访问未收敛

- **文件**：`Domain/Services/LyricsService.swift`，第 46 行、第 329-347 行

### 🟢 优化（2 项）

- **文件**：`Domain/Services/WebDAVService.swift`，第 108 行

## 总体评价

### 正面改进

1. **展示逻辑分离完成度高**：7 项 displayName/iconName/durationText/formattedSize 全部成功移至 Presentation extension，Domain Entity 现在是纯业务模型
2. **DI 改善明显**：PlaybackService 从"内部创建子 Service"改为全部 init 注入；WebDAVService 的 accountStore 已走协议注入；LyricsService 的 API 客户端已走协议注入
3. **线程安全加固**：UndoToken 加 @MainActor，Timer 加 .common mode，scheduleCommit 防护完善
4. **API 语义改善**：SearchResult 的 totalMatchCount 命名更准确，.empty 静态属性减少样板代码
5. **CloudDriveProvider 架构合规**：UIApplication 调用已正确移至 App 层
6. **正则安全性**：LyricsService 的 lrcRegex 改为 try! 编译期保证

### 仍需改进（均为渐进改进项）

1. **import UIKit 残留**（3 个 Service）：根因是封面缩略图处理链路贯穿 Domain 层，需要较大重构将图片处理抽象为协议
2. **Core 层单例硬引用**（AudioSessionManager/NowPlayingManager/FileStorageService/ImageCacheManager）：PlaybackService 和 MusicLibraryService 仍直接调用
3. **UserDefaults 分散访问**：PlaybackService 和 LyricsService 均有多处直接 UserDefaults 读写

> 以上 3 类问题均已标注 TODO，属于架构渐进改进方向。修复需要较大的重构工作量（提取协议层 + 修改 DI 容器 + 更新所有调用点），建议在专门的重构迭代中统一处理。
