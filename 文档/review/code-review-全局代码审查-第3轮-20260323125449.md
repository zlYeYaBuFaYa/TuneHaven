## 🔴 阻塞问题（共 13 项）

### 架构合规（3 项）

#### 🔴-01 WebDAVService 仍直接绑定具体类型，无协议抽象

- **文件**：`Domain/Services/WebDAVService.swift`，第 14-15 行
- **描述**：`accountStore = WebDAVAccountStore.shared`（Data 层单例）、`activeClient: WebDAVClient?`（Core 层具体 actor），Domain Service 对 Data/Core 层形成硬依赖。第 1 轮标记为"渐进改进"，至今未改。
- **建议**：定义 `WebDAVAccountStoreProtocol` + `WebDAVClientProtocol`，init 注入协议，AppDIContainer 组装具体实现

#### 🔴-02 PlaybackService 内部大量硬依赖 Core 层单例

- **文件**：`Domain/Services/PlaybackService.swift`，第 18-23 行
- **描述**：直接引用 `AudioEngine.shared`、`AudioSessionManager.shared`、`NowPlayingManager.shared`、`FileStorageService.shared`、`ImageCacheManager.shared` 五个 Core 层单例，且内部创建 `PlayQueueService()` 和 `MusicLibraryService(songRepo:)` 绕过 DI 容器
- **建议**：为关键依赖定义 Domain 层协议并通过 init 注入；子 Service 由 AppDIContainer 统一创建

#### 🔴-03 CloudDriveProvider Domain 层直接调用 UIApplication

- **文件**：`Domain/Services/CloudDriveProvider.swift`，第 16-19 行
- **描述**：`CloudDriveInstallChecker.isInstalled` 在 Domain 层使用 `UIApplication.shared.canOpenURL`，`#if canImport(UIKit)` 不解决架构分层问题
- **建议**：将 `CloudDriveInstallChecker` 移至 App 层或 Presentation 层

### Data 层数据安全（1 项）

#### 🔴-09 CoreDataSongRepository softDelete count 查询 try? 可能误删文件

- **文件**：`Data/Repositories/CoreDataSongRepository.swift`，第 169 行
- **描述**：`softDelete` 计算文件引用数时 `(try? ctx.count(for: countReq)) ?? 0`，count 查询失败默认为 0，导致误判"无其他引用"，仍被其他歌曲引用的文件被移到待删除目录
- **建议**：改为显式 `try`，查询失败时整个 softDelete 回滚并报错
