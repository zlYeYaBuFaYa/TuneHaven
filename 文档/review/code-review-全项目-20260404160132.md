## 二、各层 Review 结论

### 2.1 Core 层（~35 文件）

**整体评价**：质量较高，基础设施层设计稳固。

- **架构**：Audio/Cache/Network/Persistence/Storage/Utils 划分合理，无跨层依赖
- **并发**：`AudioEngine` 状态管理通过 `@MainActor` + Combine Publisher，线程安全
- **重点修复**：`ShareClient` 代码重复（已修复）

**🟡 重要级建议**（未修复，待后续跟进）：
- `CoreDataStack` 的 `performBackground` 闭包未限制 `@Sendable`，理论上可捕获非 Sendable 值
- `NWListener` 在 `ShareServer` 中的错误重试逻辑未设上限

### 2.2 Domain 层（~30 文件）

**整体评价**：核心业务逻辑层，修复了多个阻塞级问题。

- **架构**：Entities/Repositories(协议)/Services 三层清晰，面向协议编程
- **并发**：`ShareService` 回调线程安全已修复；`SubscriptionService` 内存泄漏已修复
- **封装**：`PlaybackService` 的 `private(set)` 已加固

**🟡 重要级建议**：
- `PlaybackService` 的 `setupBindings()` 中 `engine.stateSubject.sink` 闭包较长（~50 行），可提取子方法
- `WebDAVService.downloadTasks` 数组在并发 `TaskGroup` 中被引用，虽通过 index 访问但需关注 `@MainActor` 边界

### 2.3 Data 层（~20 文件）

**整体评价**：Core Data 实现规范，Mapper 层清晰。

- **架构**：Repository 实现与 Domain 协议对齐，`SongMapper`/`PlaylistMapper` 双向转换
- **重点修复**：软删除恢复逻辑、WebDAV 账户解码错误日志

**🟡 重要级建议**：
- `AudioMetadataParser` 对部分格式的元数据提取依赖 AVAsset 异步加载，超时处理可考虑添加

### 2.4 Presentation 层（~40 文件）

**整体评价**：SwiftUI 视图整体结构良好，发现并修复了性能和安全问题。

- **架构**：按功能模块划分（Player/Library/Playlist/Import/Share/Settings/Subscription）
- **重点修复**：进度条拖拽节流、歌词索引刷新优化、PaywallView URL 安全

**🟡 重要级建议**：
- 部分大型视图文件（如 `LibraryView.swift`、`PlaylistDetailView.swift`）行数较多，可拆分子视图
- `FullScreenPlayerView` 中嵌套 `GeometryReader` 层级较深，需关注布局性能

### 2.5 App 层（~25 文件）

**整体评价**：DI 容器设计合理，主题系统完善，无阻塞级问题。

- **架构**：`AppDIContainer` 集中管理依赖，`lazy var` 延迟创建非首屏服务
- **主题**：`ThemeRegistry` + `ThemeManager` + `ThemeStyle` 扩展模式易于新增主题
- **导航**：`AppRouter` + `NavigationPath` 类型安全导航

**🟢 轻微建议**：
- `ThemeManager.currentTier` 的 `didSet` 使用 `tierInitialized` 标记略显复杂，可考虑改为方法调用
- `CosmicParticlesBackground` 使用 15fps Canvas，可增加 `drawingGroup()` 优化渲染管线

### 2.6 测试代码（22 文件）

**整体评价**：核心服务有测试覆盖，但部分测试断言偏弱。

**优点**：
- `PlayQueueService`、`SearchService`、`PlaylistService` 命名校验、`AudioFormat`、歌词解析等有实质性断言
- Swift Testing (`@Suite` / `@Test`) 使用规范，命名清晰
- Mock 层覆盖主要 Repository 协议

**🟡 重要级建议**：
- `P0FixTests` 使用 `CoreDataStack.shared` 全局单例，并行测试存在隔离风险
- `ThemeRegistryTests` 操作全局 `ThemeRegistry.shared`，建议添加 `.serialized` trait
- 部分测试使用 `#expect(true)` 等弱断言，信息量低
- 缺少 `PlaybackService` 状态机、`WebDAVService` 网络层、`ShareService` 完整流程的单元测试
