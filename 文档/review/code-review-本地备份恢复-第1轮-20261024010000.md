## 问题

### 🔴 阻塞

1. 合并替换时，包内封面或歌词还没复制成功，歌曲记录就已经改成新路径。源文件缺失时 `clearMissing` 再把封面设为 nil，成功提交后旧封面会被当成无人引用而删除。
2. 替换曲库会删掉旧分组，但保留的系统歌单仍带着原来的 `groupId`。
3. 从「文件」或 Inbox 打开 `.tunehaven` 时，复制失败也会删掉 Inbox 里的原件。
4. 新音频若放在 `Music/backup/` 子目录，`URL.appendingPathComponent` 会把斜杠编码进一个路径组件，播放和待删除都对不上。

### 🟡 重要

1. `FileManager` 的文件大小是 `NSNumber`，`as? Int64` 经常得到 0，预估体积和 4GB 前提判断失效。
2. 恢复写入 Core Data 之前没有停止播放，播放进度可能和快照保存交错。
3. 导出中途失败会留下未写完的 zip。
4. 无法识别的主题 id 会留在 `theme_style`，界面虽回退默认主题，偏好仍是脏值。
5. 歌词来源用 `Int16(_:)`，包内异常整数会陷阱崩溃。
6. 外部备份按原文件名覆盖 `backup_incoming`，后一次打开会拆掉前一次还在读的文件。

### 🟢 轻微

1. 分组 `sortOrder == 0` 被当成「未设置」改写成序号。
2. ZIP 本地文件头的 `offset` 参数没有使用。
3. 歌单链接的 `sortOrder` 用 `Int32(offset)`，超大歌单会陷阱。
4. 偏好测试用 `bool(forKey:)` 判断 `false`，键没写上也会通过。
5. 缺失音频查询只匹配 `missing/` 前缀，空路径挂不回来。
