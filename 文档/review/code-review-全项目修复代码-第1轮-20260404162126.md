## 问题清单

### 1. [🔴 阻塞] SubscriptionService 内存泄漏修复不完整

**文件**：`Domain/Services/SubscriptionService.swift` 第 121-128 行

**问题**：第 122 行 `guard let self else { return }` 创建的强引用局部变量作用域覆盖整个 Task 闭包体（包括 `for await` 循环）。即使第 124 行有 `guard let self else { break }`，外层强 `self` 仍持有 `SubscriptionService`，阻止释放。

**修复**：将 `guard let self` 改为 `guard let provider = self?.provider`，仅提取 `provider` 引用，不在循环外持有 `self`。

```swift
// 修复前
transactionTask = Task { [weak self] in
    guard let self else { return }  // 强 self 作用域覆盖整个 Task
    for await update in self.provider.transactionUpdates() {
        guard let self else { break }  // 被外层强 self 遮蔽
        ...
    }
}

// 修复后
transactionTask = Task { [weak self] in
    guard let provider = self?.provider else { return }
    for await update in provider.transactionUpdates() {
        guard let self else { break }  // 现在是唯一的 self 引用
        ...
    }
}
```

### 2. [🟡 重要] ShareClient 强制解包

**文件**：`Core/Network/ShareClient.swift` 第 239 行

**问题**：`downloadToDestination(allow404: false)!` 使用强制解包。虽然逻辑上 `allow404: false` 时不会返回 `nil`，但依赖隐式契约，未来修改 `downloadToDestination` 可能引入崩溃。

**修复**：改为 `guard let destURL = ... else { throw AppError.fileSystemError("下载失败：未获取到文件") }`

### 3. [🟢 轻微] PaywallView 分隔符无条件渲染

**文件**：`Presentation/Subscription/PaywallView.swift` 第 282 行

**问题**：`Text("·")` 分隔符在两个 `if let` URL 绑定之间无条件渲染，若其中一个 URL 创建失败（虽几乎不可能），布局不正确。

**修复**：将 URL 提前计算，分隔符仅在两者均存在时渲染。
