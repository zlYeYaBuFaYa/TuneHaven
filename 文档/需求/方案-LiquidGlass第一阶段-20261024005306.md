# 方案：Liquid Glass 第一阶段

> 创建日期：2026-10-24 | 状态：已完成

## 1. 需求概述

产品已拍板走 B。拼音验收已通过，A（`UIDesignRequiresCompatibility`、iOS 18.0、隐私清单）已在 `feat/subscription` 的 `5e48899`。

在部署目标仍为 iOS 18.0 的前提下，用 `#available(iOS 26, *)` 分流：iOS 26 及以上开始使用 Liquid Glass，同时保留现有自绘主题和自绘 Tab。不迁移到系统 `TabView`，不使用 `tabViewBottomAccessory`。

兼容键本期不删。代码在系统版本之外再读这个键：键为真时保持现在的旧外观；关掉键且系统为 iOS 26+ 时才走玻璃路径，供 Xcode 26 对照验收。换 iOS 27 SDK 打包前必须删除该键。

必须完成：

1. iOS 26+ 且兼容键关闭：不再把导航栏设成不透明 `configureWithOpaqueBackground`。低版本，或键仍开着，保持现状。
2. 审视 sheet / fullScreenCover 的 `.presentationBackground`，避免和玻璃叠在一起把对比度冲掉。
3. `RootTabView` 自绘 Tab：玻璃路径把 `.ultraThinMaterial` 换成 `glassEffect`。保留自绘 Tab。
4. 付费墙和四套主题在各自浅色/深色下做 WCAG 对比度修正。继续用色板，视图里不用裸 `.red` / `.white`。
5. README 和技术设计记下第一阶段，并写明兼容键在换 27 SDK 前必须删除。

不做：系统 TabView、NavigationSplitView、多 Window、新的 StoreKit 展示、白屏、备份恢复。

## 2. 现状分析

- `AppDelegate.applyNavigationBarAppearance` 和 `ThemeManager.updateNavigationBars` 都调用 `configureWithOpaqueBackground()`，并把 `palette.surface` 写成导航栏底色。
- 大量页面另有 `.toolbarBackground(palette.surface)`。只改 UIKit appearance 时，这些调用仍会铺死导航栏。
- `RootTabView` 自绘 Tab 背景是 `Rectangle().fill(.ultraThinMaterial)`。迷你播放条仍是材质，本期不改。
- `.presentationBackground` 只有两处，都在 `RootTabView`：播放器全屏是色板渐变；路由 sheet（含付费墙）是 `elevatedSurface`。其余 sheet 没有这层修饰，玻璃路径下会走系统 sheet。
- 四套主题的 `onPrimary` 都是 `.white`。白字落在素云白简 `#4CAF82`、晴空蔚蓝 `#4A9FD8`、暮光玫瑰 `#E87B8A`、星际穹顶 `#00D4AA` 上，对比度分别约为 2.71、2.90、2.75、1.91，付费墙主按钮和「推荐」胶囊都不够 4.5:1。浅色主题的 `primary` 作为文字落在背景上同样不够。浅色 `textSecondary` / `textTertiary` 和浅色语义红 `#EF4444` 也不够。
- `Info.plist` 里 `UIDesignRequiresCompatibility` 为布尔真值。A 的注释仍写「本期不做 Liquid Glass」。

受影响文件：`AppDelegate.swift`、`ThemeManager.swift`、新建 `LiquidGlassPolicy.swift`、`RootTabView.swift`、四套 `ThemeStyle+*.swift`、`ThemeColorPalette.swift`、所有 `.toolbarBackground(palette.surface)` 的页面、`Info.plist`、README、三份根目录文档、方案与 Review。测试新增策略与对比度用例。

## 3. 技术方案

### 3.1 整体设计

新增 `LiquidGlassPolicy`（App/Theme，UI 基础设施，不进 Domain）。纯函数决定路径，视图和 UIKit 外观都调用它，避免两处判断不一致。

玻璃路径同时满足两点：

- `#available(iOS 26, *)` 为真
- `UIDesignRequiresCompatibility` 不为真

只写 `#available` 时，显式 `glassEffect` 在兼容键开着的包里仍可能画出玻璃，和「26 SDK + 键 → 旧外观」不一致。键继续留在 plist，本 PR 不删；运行时读取是为了让开/关键的验收结果稳定。`glassEffect` 本身仍必须包在 `#available` 里，否则旧系统编译不过。

自绘 Tab 保持 `RootTabView.customTabBar`，不换成 `TabView`。

### 3.2 详细实现

**导航栏**

- 玻璃路径：不调用 `configureWithOpaqueBackground`，也不写入 `backgroundColor`。全局 appearance 和已有 `UINavigationController` 都跳过，交给系统。
- SwiftUI 侧 `.toolbarBackground(palette.surface)` 收到 `themeNavigationBarSurface()`。玻璃路径用 `.automatic`；旧路径仍是 `palette.surface`。音乐库根页在旧路径、且主题有自绘背景时，继续用 `.ultraThinMaterial`。
- 旧路径：集中在 `opaqueNavigationBarAppearance(surfaceColor:)`，`AppDelegate` 与 `ThemeManager` 共用，避免两份不透明配置再次分叉。

**presentationBackground**

- 路由 sheet：玻璃路径且主题没有自绘背景时，去掉不透明 `elevatedSurface`，让系统 sheet 玻璃生效。内容区已有不透明 `palette.background`，正文不直接落在透底上。
- 星际穹顶有粒子背景，页面底是透明的。玻璃路径仍保留不透明 `elevatedSurface`，否则文字会压在动态背景上。
- 播放器 fullScreenCover：任何路径都保留色板渐变。播放器文字落在这块渐变上，透出曲库会破坏对比度。

**自绘 Tab**

玻璃路径：

```swift
Rectangle()
    .fill(Color.clear)
    .glassEffect(.regular.tint(surface.opacity(0.45)), in: Rectangle())
```

`surface` 来自色板，给玻璃一层与主题深浅一致的着色，避免标签直接压在封面上来回变色。不用 `.interactive()`，避免整条栏变成一颗玻璃按钮。旧路径保持 `.ultraThinMaterial`。

**对比度（WCAG 4.5:1，相对亮度）**

浅色两套压深主色，使白字（`onPrimary` 写成 `#FFFFFF`，不再写 `.white`）和「主色作为文字」同时过线：

### 3.3 备选

曾考虑只改 `AppDelegate`、不改 SwiftUI `toolbarBackground`。那样主 Tab 的导航栏仍是不透明 surface，验收里开/关兼容键看不出导航差异。因此导航栏样式收口到一个修饰符。

曾考虑玻璃路径也拿掉播放器的 presentation 渐变。播放器背后是曲库，透底会让歌名对比度随封面变化。保留不透明渐变。

## 4. 影响范围

- 导航栏、自绘 Tab、路由 sheet、四套主题里用主色/次级文字/语义红的界面（含付费墙按钮）。
- 迷你播放条、系统 Tab、分栏、StoreKit 展示、兼容键本身：不改。
- 无数据库变更。iOS 18 行为与现在一致（兼容键在 iOS 18 上不会打开玻璃路径）。
- 编译 `glassEffect` 需要 Xcode 26 SDK。部署目标仍是 iOS 18.0。

## 5. 测试要点

- 纯函数：iOS 26 + 键开 → 旧导航 / 超薄 Tab / 不透明 sheet；iOS 26 + 键关 + 无自绘背景 → 系统导航 / 玻璃 Tab / 系统 sheet；有自绘背景的 sheet 仍不透明；iOS 18 即使键关也走旧路径。
- plist 值：`true` / `false` / `"YES"` / `"true"` / `"NO"` / `nil`。
- 四套主题：textPrimary、textSecondary、textTertiary、primary、onPrimary、playerSubtext、iconSecondary 相对 background、surface、elevatedSurface、playerBackground 达到 4.5:1；次级文字对比度高于三级文字；浅色/深色语义红落在对应背景上达到 4.5:1。
- 云端无 Xcode，不能跑 `xcodebuild`。本机清单见 PR。

## 6. 风险评估

- 浅色主色变深，品牌绿/蓝会比现在沉。这是按钮白字和主色文字要同时过 4.5:1 的结果。
- 迷你播放条仍是超薄材质，玻璃 Tab 打开后可能和它叠成两层。本期按范围不动，验收时只观察。
- 兼容键若在未来系统被忽略，玻璃路径会在仍带该键的包上提前生效。27 SDK 打包前必须删键，文档已写明。
- `glassEffect` 的 `tint` 签名以 Xcode 26 SDK 为准。云端无法编译，本机清单覆盖 Tab。

## 修订

第 1 轮 Review 有三条：只靠 `#available` 不能保证兼容键开着时仍是旧外观；只改 AppDelegate 时 SwiftUI 的不透明 toolbar 还在；自绘背景的 sheet 不能拿掉不透明底。正文已按这三条写定。第 2 轮通过。
