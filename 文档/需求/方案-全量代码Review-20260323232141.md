# 方案：全量代码 Review

> 创建日期：2026-03-23 | 状态：已审核（Review 2 轮通过）

---

## 1. 需求概述

TuneHaven 项目经过多轮迭代，累计 140 个 Swift 源文件。现需对全项目代码进行一次系统性 Code Review，目标：

- **发现并记录**所有代码质量问题（不同步修复）
- **按架构分层**划分模块，多 Agent 并行协作
- 大模块二次拆分为子任务，降低单次 Review 复杂度
- 所有问题汇总到**一份文档**，统一管理等级与状态

---

## 2. 现状分析

### 2.1 项目规模

| 架构层 | 文件数 | 占比 |
|--------|--------|------|
| Presentation | 54 | 38.6% |
| Domain | 34 | 24.3% |
| App | 24 | 17.1% |
| Core | 20 | 14.3% |
| Data | 8 | 5.7% |
| **合计** | **140** | **100%** |

### 2.2 技术栈

- Swift 5.0/6.0 + SwiftUI + Combine + async/await
- Clean Architecture + MVVM（Service 即 ViewModel）
- Core Data 持久化 + AVFoundation 音频引擎
- AppDIContainer 依赖注入 + 部分 .shared 单例

### 2.3 已知风险点（历史迭代遗留）

- 多轮 Bug 修复和功能优化可能引入不一致的代码风格
- DI 容器注入与 .shared 单例混用
- 多次 UI 重构可能导致残留代码或重复逻辑
- 后台播放、主题切换等反复修复的功能需重点关注

## 3. 技术方案

### 3.1 Review 维度（10 项）

#### A. 正确性与安全（4 项）

| # | 维度 | 检查要点 |
|---|------|----------|
| 1 | **逻辑正确性** | 业务逻辑完整、边界条件充分、状态一致、竞态防护 |
| 2 | **错误处理** | AppError 统一类型、传播链完整（Core/Data→Service→View）、ErrorLogger 记录 |
| 3 | **安全** | 输入校验、SandboxPathManager 路径、SecurityScoped URL、无硬编码敏感信息 |
| 4 | **线程安全** | @MainActor 正确、CoreData 双上下文、Combine sink 桥接、weak self |

#### B. 质量与规范（3 项）

| # | 维度 | 检查要点 |
|---|------|----------|
| 5 | **架构合规** | Clean Architecture 分层、依赖单向、Repository 隔离、Service 即 ViewModel |
| 6 | **代码风格** | 驼峰命名、Swift 惯用法、格式一致、访问控制合理、无冗余代码 |
| 7 | **API 设计** | 接口语义清晰、参数合理、async throws 一致、与现有风格统一 |

#### C. 性能与可维护（3 项）

| # | 维度 | 检查要点 |
|---|------|----------|
| 8 | **性能** | 复杂度合理、无循环引用、避免不必要的计算/视图重建、懒加载 |
| 9 | **内存管理** | [weak self] 正确、大对象及时释放、cancellables 正确存储 |
| 10 | **可维护性** | SOLID、DRY、低耦合高内聚、职责单一、可扩展 |

### 3.2 问题分级

| 等级 | 标识 | 定义 | 示例 |
|------|------|------|------|
| 阻塞 | 🔴 | 逻辑错误、崩溃风险、安全漏洞、数据丢失 | 未处理的 force unwrap、竞态条件、硬编码密钥 |
| 重要 | 🟡 | 性能隐患、可维护性问题、架构违规 | 循环引用、依赖方向错误、大量重复代码 |
| 轻微 | 🟢 | 风格微调、命名优化、小性能改善 | 命名不规范、多余 import、可简化的表达式 |

### 3.4 执行策略

#### 并行分组

子任务之间无强依赖，可按以下分组并行执行：

| 批次 | 并行子任务 | Agent 数 | 说明 |
|------|-----------|---------|------|
| 第 1 批 | 1.1 App核心 + 2.1 Entities + 3.1 Data + 4.1 Audio + 5.1 Common | 5 | 各层核心模块 |
| 第 2 批 | 1.2 Theme + 2.2 Repositories + 4.2 Network + 5.2 Library + 5.3 Player | 5 | 各层次要模块 |
| 第 3 批 | 2.3 Services + 4.3 基础设施 + 5.4 Playlist + 5.5 Import + 5.6 Settings | 5 | 剩余模块 |

> 每批内的子任务完全独立，可由不同 Agent 并行执行。如资源允许，15 个子任务可全部并行。

#### 单个子任务执行流程

```
1. 读取该子任务所有文件源码
2. 逐文件按 10 项 Review 维度检查
3. 发现问题按格式记录（编号、等级、状态、文件、行号、描述、建议）
4. 输出该子任务的 Review 结果
5. 标记子任务状态为 completed
```

#### 汇总流程

```
1. 所有子任务完成后，汇总各子任务的问题到一份文档
2. 按模块分章节组织
3. 生成统计摘要（各等级问题数量、各模块问题分布）
4. 输出最终的全量 Review 报告
```
