# 方案：分享接收端不信任发送端文件名（Review T1，含 ifa_addr 空指针）

> 创建日期：2026-11-17 | 状态：已完成

## 1. 需求概述

分享直传的接收端 `ShareClient` 下载音频、封面、歌词时，用发送端 `Content-Disposition` 给出的文件名拼本地路径，只做了 `lastPathComponent`。发送端返回 `filename=".."` 时，目标路径变成接收临时目录的上级（`syncExtractURL`），随后 `fileExists` → `removeItem` 会删掉整个目录，再把下载文件移过去；`"."` 则删掉本次临时目录。用户只要扫了恶意二维码就会触发。

一并修复：`WiFiTransferServer` 与 `ShareServer` 遍历 `getifaddrs` 时直接解引用 `ifa_addr.pointee`，部分接口的 `ifa_addr` 为 NULL，会直接崩溃。

验收标准：

1. 本地文件名完全由接收端决定：`{类型}_{序号}.{扩展名}`，不含发送端提供的任何路径字符。
2. 扩展名只在对应白名单内才采用（音频：支持的音频格式；封面：jpg/jpeg/png；歌词：lrc/txt），否则用默认扩展名（音频 `dat`、封面 `jpg`、歌词 `lrc`）。
3. 发送端返回 `..`、`.`、`../x.mp3`、带 `/` 的名字时，不删除、不写入目标目录以外的任何文件。
4. 正常分享流程不变：`ShareService` 仍按下载文件扩展名与歌曲标题导入。
5. 遍历网卡时跳过 `ifa_addr` 为空的接口，不崩溃。

## 2. 现状分析

| 文件 | 现状 |
|------|------|
| `Core/Network/ShareClient.swift` | `suggestedFilename` 解析 `Content-Disposition`（含 `filename*=`），取 `lastPathComponent`；`performDownload` / `performOptionalDownload` 中 `destURL` 已存在则先 `removeItem` 再 `moveItem`；`URLSession` 为 lazy `.default` 配置，无法注入 |
| `Domain/Services/ShareService.swift` | 用 `audioURL.pathExtension` 拼导入文件名；封面复制为 `{id}_medium.jpg`；歌词按下载文件扩展名保存 |
| `Core/Network/WiFiTransferServer.swift:545`、`ShareServer.swift:498` | `ifa_addr.pointee` 未判空 |
| 测试 | 无 ShareClient 测试；`WebDAVDownloadTests` 内有 private 的 URLProtocol 桩 |

## 3. 技术方案

### 3.1 ShareClient

- 新增 `enum DownloadKind { audio, cover, lyrics }`，各自给出前缀、扩展名白名单、默认扩展名：

| kind | 前缀 | 白名单 | 默认 |
|------|------|--------|------|
| audio | `audio` | `FileStorageService.supportedExtensions` | `dat` |
| cover | `cover` | jpg、jpeg、png | `jpg` |
| lyrics | `lyrics` | lrc、txt | `lrc` |

- 新增 `static func localFilename(for response: HTTPURLResponse, kind:, index:) -> String`：用现有 `parseFilename` 取发送端名字，只读其 `pathExtension`（小写），在白名单内则采用，否则用默认；返回 `"\(prefix)_\(index).\(ext)"`。
- `performDownload` / `performOptionalDownload` 改为接收 `kind`、`index`，用 `localFilename` 生成名字；删除 `suggestedFilename` 与 `fallbackFilename` 参数。
- 写入前校验：`destURL.deletingLastPathComponent().standardizedFileURL == destinationDirectory.standardizedFileURL`，不满足则删除临时下载文件并抛错（由构造保证不会发生，作为防御）。
- 新增 `init(sessionConfiguration: URLSessionConfiguration = .default)`，`urlSession` 用注入配置的副本并保留原超时设置；仅供测试注入 URLProtocol 桩。

### 3.2 ifa_addr 判空

两处循环开头 `guard let addr = ptr.pointee.ifa_addr else { continue }`，后续用 `addr` 代替 `ifa_addr`。

### 3.3 测试基础设施

把 `WebDAVDownloadTests` 中的 `StubURLProtocol` 移到 `TuneHavenTests/TestHelpers/StubURLProtocol.swift`（internal），`Response` 增加 `headers: [String: String]`。WebDAV 测试改用共享版本。

## 4. 影响范围

- 下载到临时目录的文件名从发送端原名变为 `audio_3.flac` 这类名字；`ShareService` 只用扩展名，导入名由歌曲标题决定，库内文件名不变。
- 发送端协议、`ShareServer`、`ShareService` 不变。
- ifa_addr 判空只在异常接口上生效，正常地址解析结果不变。

## 5. 测试要点

新增 `TuneHavenTests/ShareClientTests.swift`（URLProtocol 桩，先 `connect` 再下载）：

1. 发送端文件名为 `..`：文件保存在目标目录内（`audio_0.dat`），目标目录的上级中预置的哨兵文件仍在。
2. `../../evil.mp3`：保存为目标目录内的 `audio_1.mp3`。
3. 音频扩展名不在白名单（`x.exe`）：保存为 `audio_2.dat`。
4. 封面 `A.PNG`：保存为 `cover_5.png`。
5. 歌词 `filename*=utf-8''%E6%AD%8C.lrc`：保存为 `lyrics_5.lrc`。
6. 可选下载 404：返回 nil，目标目录无文件。
7. `localFilename` 纯函数：无 `Content-Disposition` 时用默认扩展名。

回归：全量 `TuneHavenTests`（含迁移桩后的 WebDAV 测试）。

ifa_addr 判空依赖系统网卡列表，无法构造空地址接口，不加单测，靠代码 Review。

## 6. 风险评估

| 风险 | 应对 |
|------|------|
| 发送端是旧版本、文件名带特殊扩展名（如 `.alac`） | `alac` 在支持列表内；其余未知扩展名按 `dat` 导入会被判格式不支持，与修复前把 `.dat` 兜底名导入的结果一致 |
| 移动测试桩影响 WebDAV 测试 | 行为不变，只是位置共享；全量回归覆盖 |
