# 方案：本地备份恢复

> 创建日期：2026-10-24 | 状态：已完成 | 需求数：1
>
> 产品说明以附件《本地备份 / 恢复》为准。云端任务已明确「以附件为准、直接实现并开 PR」，不中断等待二次口头确认。NOTE-PY-01/02 不在本期。不改订阅门禁、拼音匹配、PrivacyInfo / iOS 26 兼容。

## 1. 需求概述

Free 用户无需账号、不走 Premium，把曲库与指定偏好打成单个 `.tunehaven` 包，经系统分享 / Files 导出；同机或换机时从包恢复。恢复三模式：合并（推荐）、替换曲库、仅恢复偏好。解包只发生在临时目录，数据库与正式音频目录在提交成功前保持原样；失败删除本次新建文件并放弃数据库写入，不留下半成品曲库。

不包含：StoreKit 权益、Keychain、WebDAV 账号与密钥、播放次数、跳过权重、搜索历史、睡眠定时进行中状态、「最近播放」历史列表、iCloud / 后台云同步。

## 2. 现状分析

- 旧 `.tunehaven` 打包器已随二维码分享方案移除。分享直传是选择性局域网传输，不承担整库灾备。
- 歌曲、歌单、分组在 Core Data；主题 / 播放模式 / 速度记忆 / 歌词字形在 UserDefaults（`AppStorageKey`）。
- 「我喜欢」由 `isFavorite` 推导，不依赖歌单曲目表。「最近播放」由 `lastPlayedDate` 推导。
- `MissingSongReferenceEntity` 未被业务使用。缺失音频用 `fileRelativePath` 前缀 `missing/` 表示，播放前已有「文件不存在」判断；列表行补充灰色「未找到」。日后普通导入按哈希或「标题+艺人+专辑+时长」挂回。
- 工程使用同步根组，新 Swift 文件不必改 `pbxproj`。

## 3. 技术方案

### 3.1 整体设计

依赖方向：Presentation → Domain ← Data，文件与 ZIP 在 Core。

```
设置 / onOpenURL
    → BackupRestoreService
        → BackupExporter + ZipStoreArchive     导出
        → BackupPackageCodec                   临时目录解包
        → BackupPlanner                        纯函数：三模式与冲突
        → BackupCommitter                      只新增文件，再提交快照
        → BackupLibraryApplying
              CoreDataBackupLibraryStore       单次 background save
              （测试用内存实现）
        → BackupPreferenceStore                仅 4 个允许键
```

包结构（ZIP method 0，UTF-8 文件名）：

```
manifest.json
preferences.json
groups.json
playlists.json
songs.json
audio/{id}.{ext}
covers/{id}.jpg
lyrics/{id}.lrc
```

`manifest.formatVersion = 1`。含 `appVersion`、`exportedAt`、`includesAudio`、条目数、`payloadBytes`。

偏好仅：`theme_style`、`play_mode`、`speed_memory_mode`、`lyrics_simplified`。

歌曲冲突：主匹配「标题+艺人+专辑+时长」（时长差 `< 2` 秒，专辑空与「未知专辑」等价），兜底「标题+艺人」。选项：替换 / 跳过 / 另存副本。默认「应用到全部」，初始选择为跳过（不破坏现有曲目）；用户可改。未应用到全部时按条目覆盖。

歌单冲突（按名称，系统歌单名称不导入）：替换 / 合并（已有保留、没有则追加）/ 新建副本。默认应用到全部，初始选择为合并。

替换曲库：二次确认后，快照中只保留系统歌单结构；自建歌单与自建曲目删除后再导入。收藏靠 `isFavorite` 恢复。最近播放历史不进包。不含音频的替换会使新曲目成为「未找到」，确认文案写明。

合并时若选择替换但包内该曲没有音频、本地却有音频：更新文案与收藏，保留本地音频，避免精简包把可播文件抹掉。整库替换不受此保护。

提交顺序：

1. ZIP 解到 `tmp/backup_extract/<session>/`，拒绝 `..`、绝对路径、反斜杠（zip slip）。
2. 把需要的音频 / 封面 / 歌词复制到**尚不存在**的新相对路径（已存在则加后缀）。事务只记录本次新建文件。
3. 一次 `library.apply`。Core Data 实现先 `save`，成功后再写 4 个偏好键。
4. `apply` 抛错，或在进入 `apply` 之前取消：删除本次新建文件，不写偏好，不改已有文件。取消只在逐文件复制循环里以及调用 `apply` 之前生效。Core Data 的单次 `save` 开始后不再从中切断，避免半次保存。
5. 成功后才最佳努力删除不再引用的旧文件；这一步失败只记日志（不含完整路径），不回滚已提交曲库。提交前崩溃留下的新文件没有数据库引用，不覆盖旧路径。
6. 成功后若不是「仅偏好」，停止播放并刷新曲库 / 歌单 / 分组。主题走 `ThemeManager.reloadStoredStyle()`，内部仍调用现有 `enforceThemeAccess()`，不改订阅判断。

ZIP32 中央目录偏移超过约 4GB 时导出失败，提示改用仅元数据。导出前展示预估体积。

与导入互斥：`BackupActivityGate`。备份进行中普通导入直接失败返回，不穿插写库。

打开 `.tunehaven`：`Info.plist` 登记类型，`onOpenURL` 拷到 incoming 后弹出恢复预览。不删除用户 Files 里的原包（仅清理 Inbox 副本，沿用现有规则）。

### 3.2 详细实现

| 文件 | 职责 |
|------|------|
| `Domain/Entities/BackupTypes.swift` | 包模型、模式、冲突、快照、摘要 |
| `Domain/Services/BackupSongMatcher.swift` | 匹配与保留歌单名 |
| `Domain/Services/BackupPlanner.swift` | 三模式纯函数 |
| `Domain/Services/BackupExporter.swift` | 快照 → 目录草稿 |
| `Domain/Services/BackupPackageCodec.swift` | JSON + 调用 ZIP；解包校验 |
| `Domain/Services/BackupCommitter.swift` | 只新增文件的事务，再 `apply` |
| `Domain/Services/BackupPreferenceStore.swift` | 允许键读写 |
| `Domain/Services/BackupRestoreService.swift` | UI 状态、进度、取消、分享 URL |
| `Core/Storage/ZipStoreArchive.swift` | store 方法 ZIP 读写（不引用 Domain） |
| `Data/Repositories/CoreDataBackupLibraryStore.swift` | 快照加载与单次提交 |
| `Presentation/Settings/SettingsBackupSection.swift` | 设置入口 |
| `Presentation/Settings/BackupCenterView.swift` | 导出 / 预览 / 三模式 / 确认 / 进度 |
| `TuneHavenTests/BackupRestoreTests.swift` | 打包、解包、三模式、回滚 |

改动点：`Song` 缺失音频前缀；`SongRepository.updateSongMedia` / `fetchSongsMissingAudio`；`ImportService` 在哈希或元数据命中缺失曲时挂回；`AppError` 四个 BKP；`SandboxPathManager` 三个临时目录；`OpenInImportHandler`；`ThemeManager.reloadStoredStyle`；设置与根视图注入；`Info.plist` 文档类型。不改 `SubscriptionService`、`PinyinSearchMatcher`、Privacy manifest。

### 3.3 备选方案

压缩 ZIP（deflate）体积更小，但音频几乎压不动，且云端难以依赖压缩框架做回滚测试。采用 store 方法，元数据体积可忽略，实现和测试只依赖 Foundation。

## 4. 影响范围

- 设置新增「备份与恢复」，与「分享」并列，不替换二维码分享。
- 导入仅在「缺失音频」曲目上多一条挂回路径；已有哈希去重不变。
- 替换曲库会硬删除不在新快照中的在库歌曲与自建歌单（软删除行保留）。
- 无 StoreKit / Keychain 读写。Free 恢复高级主题后仍由现有 `enforceThemeAccess` 降回免费主题。

## 5. 测试要点

- ZIP 往返（含中文文件名）、损坏包、非法路径不写出目标外文件。
- 仅元数据包比含音频包小，且恢复后路径为 `missing/`。
- 合并：跳过 / 替换（保留 playCount）/ 另存副本；歌单合并与新建副本；应用到全部与单条覆盖。
- 替换：自建曲目与歌单清空，系统歌单还在，收藏恢复，播放次数不进包。
- 仅偏好：曲目与音频文件不变，无关 UserDefaults 键不变。
- `apply` 失败或取消：内存曲库与预先存在的音频文件保持原样，本次新文件被删除。
- 目录 JSON 不含 playCount、subscription、keychain、webdav、password。

云端无 iOS SDK，不能跑 `xcodebuild test`。本机验证清单见 PR。

## 6. 风险评估

| 风险 | 应对 |
|------|------|
| 大库耗时 / 超过 4GB | 预估、进度、可取消、超限提示改仅元数据 |
| 替换不可撤销 | 破坏性确认文案 |
| 提交窗口崩溃留下孤儿新文件 | 新文件不覆盖旧路径；孤儿未被数据库引用，下次备份不读取 `backup/` 以外的失效引用。正式曲库仍是旧快照 |
| 恢复高级主题绕过订阅 | 不写权益；写完主题后走现有免费主题降级 |
| 日志泄密 | 不记录完整沙盒路径 |
