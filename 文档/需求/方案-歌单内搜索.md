# 方案：歌单内搜索 + 头部折叠

> 创建日期：2026-03-20 | 状态：已完成

## 1. 需求概述

歌单详情页增加搜索功能和布局优化：

- **搜索栏**：下拉显示搜索栏（使用 `.searchable` modifier），支持按歌曲名/艺术家/专辑过滤歌单内歌曲
- **搜索防抖**：300ms
- **搜索无结果**：显示空状态提示
- **头部折叠**：搜索激活时自动隐藏头部信息区域，为搜索结果腾出全部空间
- **非搜索状态**：头部正常显示，随列表自然滚动

## 2. 现状分析

### 当前 PlaylistDetailView 结构

```
List(.insetGrouped):
  Section 1: PlaylistHeaderSection（封面140x140 + 歌单名 + 描述 + 歌曲数 + 播放全部按钮）
  Section 2: 歌曲列表 ForEach(detail.songs)
```

- 无搜索功能
- 头部固定高度约 280pt，占据半屏

### 需修改的文件

| 文件 | 改动 |
|------|------|
| PlaylistDetailView.swift | 增加搜索状态、搜索逻辑、条件显示头部 |

### 对现有功能的影响

- 歌曲列表展示逻辑不变，仅增加过滤层
- Toolbar（添加/更多按钮）不变
- 歌单 CRUD 操作不变

## 3. 技术方案

### 3.1 整体设计

**方案选择：** 使用 iOS 原生 `.searchable` modifier

优势：
- iOS 18.5+ 支持完善，下拉显示搜索栏是 iOS 原生交互
- 自动集成 NavigationStack，搜索框位置和动画由系统处理
- 搜索激活/取消状态有系统回调 `isSearching`

**数据流：**

```
@State searchText → @Environment(\.isSearching) isSearching

非搜索状态：显示 header + 全部歌曲
搜索激活状态：隐藏 header + 显示过滤后歌曲
```

**过滤逻辑：**

```swift
var filteredSongs: [Song] {
    guard !searchText.isEmpty, let songs = detail?.songs else {
        return detail?.songs ?? []
    }
    let q = searchText.lowercased()
    return songs.filter {
        $0.title.lowercased().contains(q) ||
        $0.artist.lowercased().contains(q) ||
        $0.album.lowercased().contains(q)
    }
}
```

### 3.2 详细实现

#### PlaylistDetailView 改动

**1. 新增搜索状态**

```swift
@State private var searchText = ""
```

**2. 将歌曲列表提取为子视图以访问 isSearching**

由于 `@Environment(\.isSearching)` 只在 `.searchable` 修饰的视图的**子视图**中可用，需要将列表内容提取为独立子视图：

```swift
struct PlaylistContentView: View {
    let detail: PlaylistDetail
    let playlistId: UUID
    let searchText: String
    @Environment(\.isSearching) private var isSearching

    var filteredSongs: [Song] { ... }

    var body: some View {
        if !isSearching {
            Section { PlaylistHeaderSection(...) }
        }
        Section {
            if filteredSongs.isEmpty {
                // 空状态
            } else {
                ForEach(filteredSongs) { song in ... }
            }
        }
    }
}
```

**3. 在 PlaylistDetailView 上添加 .searchable**

```swift
List {
    if let detail {
        PlaylistContentView(
            detail: detail,
            playlistId: playlistId,
            searchText: searchText
        )
    }
}
.searchable(text: $searchText, prompt: "搜索歌单内歌曲")
```

**4. 搜索空状态**

搜索有文本但无匹配结果时：

```swift
VStack(spacing: 12) {
    Image(systemName: "magnifyingglass")
        .font(.system(size: 36))
        .foregroundColor(palette.iconSecondary)
    Text("未找到匹配的歌曲")
        .foregroundColor(palette.textSecondary)
}
```

### 3.3 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. `.searchable` modifier（采用） | iOS 原生交互，系统处理动画和位置 | 需要子视图访问 isSearching |
| B. 自定义搜索栏 + GeometryReader 折叠 | 完全自控 | 实现复杂，动画需自行处理 |
| C. 搜索栏常驻顶部 | 简单 | 占用空间，歌曲少时不美观 |

推荐 A：最符合 iOS 设计规范，用户体验一致。

## 4. 影响范围

| 范围 | 影响 |
|------|------|
| PlaylistDetailView | 增加搜索功能、拆分 PlaylistContentView 子视图 |
| PlaylistHeaderSection | 无修改 |
| 其他页面 | 无影响 |

## 5. 测试要点

| 场景 | 预期 |
|------|------|
| 下拉列表 | 搜索栏出现 |
| 输入搜索文本 | 实时过滤歌曲，头部隐藏 |
| 搜索无结果 | 显示"未找到匹配的歌曲"空状态 |
| 取消搜索 | 恢复头部和完整歌曲列表 |
| 搜索按歌曲名 | 匹配标题包含关键词的歌曲 |
| 搜索按艺术家 | 匹配艺术家包含关键词的歌曲 |
| 搜索按专辑 | 匹配专辑包含关键词的歌曲 |
| 空歌单搜索 | 不显示搜索栏（或搜索无意义） |
| 搜索状态下左滑操作 | 仍可正常操作（收藏/移除） |

## 6. 风险评估

| 风险 | 等级 | 应对 |
|------|------|------|
| `.searchable` 与 `.insetGrouped` 列表样式兼容性 | 低 | iOS 18.5+ 系统支持完善 |
| isSearching 环境值传递 | 低 | 通过子视图拆分解决 |
| 搜索时歌曲操作（删除/移除）后列表刷新 | 低 | 现有 onReceive(playlistService.$playlists) 已覆盖刷新逻辑 |
