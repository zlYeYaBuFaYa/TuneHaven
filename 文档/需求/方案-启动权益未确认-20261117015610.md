# 方案：启动时权益未确认（Review T2，含 T3 无损歌曲恢复）

> 创建日期：2026-11-17 | 状态：草稿

## 1. 需求概述

启动时 `SubscriptionService.loadLocalStatus()` 只用缓存权益和本地首次启动日期算档位，以便不等 StoreKit 就显示界面。以下情况会得到「临时 Free」：

- 年度订阅已在后台续费，但缓存里的到期日已过（每个年订用户每年一次）；
- 升级到带权益缓存的版本后，第一次启动还没有缓存；
- 试用期已过但仍是 Premium 用户（终身买断）且缓存为空。

临时 Free 带来两处不可逆的后果：

1. **主题被重置（高危）**：`AppDIContainer` 订阅 `$tier`，`ThemeManager.applyTier(.free)` 立即 `setTheme(.cloudWhite)` 并写回偏好；1–2 秒后 StoreKit 确认 Premium，用户选的高级主题已丢失。
2. **无损歌曲不恢复（T3 中危）**：`PlaybackService.restoreLastPlayedSong()` 在临时 Free 下拒绝把上次的无损歌曲恢复为当前歌曲，之后确认 Premium 也不补回。

目标：区分「本地推断」与「StoreKit 已确认」的档位，只在已确认时做不可逆操作；确认为 Premium 时补回被临时拦下的上次歌曲。

验收标准：

1. 本地推断为 Free、尚未确认时：显示用户已保存的主题，偏好不被改写。
2. 确认为 Free：降为素云白简并写回偏好（与现有行为一致）。
3. 确认为 Premium：主题保持不变。
4. 启动时因临时 Free 没恢复的上次无损歌曲，在档位变为 Premium 后恢复为当前歌曲，不自动播放；若用户此间已开始播放别的歌曲，则不再覆盖。
5. 真正的 Free 用户冷启动仍不把无损恢复为当前歌曲，也不弹付费墙（现有用例保持通过）。

## 2. 现状分析

| 文件 | 现状 |
|------|------|
| `Domain/Services/SubscriptionService.swift` | `loadLocalStatus()` 与 `refreshStatus()` 都只写 `tier` / `status`，外界无法区分两者 |
| `App/Theme/ThemeManager.swift` | `currentTier` 的 `didSet` 在档位变化时 `enforceThemeAccess()`；`applyTier` 赋值后再强制一次；`enforceThemeAccess` 通过 `setTheme` 写回偏好 |
| `App/AppDIContainer.swift` `setupSubscriptionBindings()` | `$tier.sink { themeManager.applyTier(tier) }` |
| `Domain/Services/PlaybackService.swift` | `restoreLastPlayedSong()` 无损且 `deniesLossless` 时直接返回；`handleTierChange` 只处理降为 Free |
| 测试 | `SubscriptionStartupTests`、`SubscriptionGateTests`（含 PlaybackHarness、主题档位用例）、`P3FixTests` 调用 `applyTier(_:)` |

## 3. 技术方案

### 3.1 SubscriptionService

- 新增 `@Published private(set) var isStatusVerified = false`。
- `refreshStatus()` 在 `apply(...)` 之后置 `true`（无论结果）。`loadLocalStatus()` 不改它。
- `resolveEntitlements()` 总会返回（离线时读 StoreKit 本地记录），因此确认通常在启动后 1–2 秒内完成。

### 3.2 ThemeManager

- `currentTier` 改为 `private(set) var currentTier: SubscriptionTier = .free`，去掉 `didSet` 与 `tierInitialized`（所有赋值都经 `applyTier`）。
- `applyTier(_ tier: SubscriptionTier, verified: Bool = true)`：
  - 赋值 `currentTier = tier`；
  - `verified` 为真时调用 `enforceThemeAccess()`；为假时不改主题、不写偏好。
- `enforceThemeAccess()` 不变（Free 且当前为高级主题 → `setTheme(.cloudWhite)`）。
- 默认参数 `verified: true` 让现有调用与测试保持原语义。
- 未确认期间 `setTheme` 仍按 `currentTier == .free` 拒绝高级主题：只影响启动后 1–2 秒内在设置页切换主题，可接受。

### 3.3 AppDIContainer.setupSubscriptionBindings

```swift
subscriptionService.$tier
    .combineLatest(subscriptionService.$isStatusVerified)
    .sink { [weak self] tier, verified in
        self?.themeManager.applyTier(tier, verified: verified)
    }
```

`refreshStatus` 先写 `tier` 再写 `isStatusVerified`，订阅者依次收到 `(新档位, false)`、`(新档位, true)`，第二次才执行降级。

### 3.4 PlaybackService

- 新增 `private var pendingLosslessRestore: Song?`。
- `restoreLastPlayedSong()`：无损被拒时记录 `pendingLosslessRestore = song`（其余行为不变：`currentSong = nil`、不设 `losslessBlockedSong`）。
- `handleTierChange(_ tier:)`：开头新增分支——`tier == .premium` 且有 `pendingLosslessRestore`：
  - 若 `currentSong == nil`：`currentSong = song`，`queueService.replaceQueue(with: [song], startAt: 0)`；
  - 无论是否恢复，清空 `pendingLosslessRestore`。
- 原有「降为 Free 暂停正在播放的无损」逻辑不变。
- 不依赖 `isStatusVerified`：本地推断为 Premium（缓存有效）时启动恢复本来就会成功，不会进入待恢复分支。

### 3.5 备选方案

确认前临时按免费主题渲染、不写偏好：权益更严格，但年订用户每次续费后启动都会看到主题先变白再变回。已确认采用「保持已存主题」。

## 4. 影响范围

- 订阅门禁本身（`canAccess`）不变：WebDAV、在线歌词、无损播放在确认前仍按本地推断档位判断。
- 真正过期的用户在过期后第一次启动时，多看到 1–2 秒高级主题；此后偏好已写回免费主题，不再出现。
- 无数据模型变更。

## 5. 测试要点

`SubscriptionStartupTests`：

1. `loadLocalStatus()` 后 `isStatusVerified == false`；`refreshStatus()` / `initialize()` 后为 `true`。

`SubscriptionGateTests`（主题与播放）：

2. 保存高级主题，`applyTier(.free, verified: false)`：`currentStyle` 与偏好都不变。
3. 接着 `applyTier(.premium, verified: true)`：主题不变。
4. 接着 `applyTier(.free, verified: true)`：降为 `cloud_white` 并写回偏好。
5. 端到端：`SubscriptionService` 缓存为空、实际为买断 → `loadLocalStatus` 后按 `(tier, isStatusVerified)` 应用主题不降级 → `initialize` 后仍为原高级主题。
6. 播放：Free 冷启动无损未恢复 → 档位变为 Premium → `currentSong` 为该无损歌曲、未自动播放、队列为 1 首。
7. 播放：未恢复期间已播放其他歌曲 → 档位变为 Premium 后不覆盖当前歌曲。

现有用例（`applyTier(_:)` 默认已确认、Free 冷启动不恢复无损）必须继续通过。回归：全量 `TuneHavenTests`。

## 6. 风险评估

| 风险 | 应对 |
|------|------|
| StoreKit 一直不返回，主题长时间保持高级 | `resolveEntitlements` 离线也会返回；最坏情况与修复前「永久丢主题」相比可接受 |
| `combineLatest` 首次同时发出 `(.free, false)` | 未确认，不降级，正是期望行为 |
| 去掉 `didSet` 后有直接赋值 `currentTier` 的代码 | 已全局搜索：只有 `applyTier` 赋值，改为 `private(set)` 由编译器保证 |
