# 方案：WiFi 上传令牌与主题门禁

> 创建日期：2026-10-24 | 状态：已完成 | 需求数：2

---
## 需求 1：WiFi 密码必须挡住上传

### 1.1 需求概述

密码开启时，只有先通过 `POST /auth` 的连接才能上传。服务器签发只存在内存中的随机 token，网页在 `POST /upload` 的 `Authorization: Bearer` 里带上。流式上传和小请求上传都要核对。服务停止、重新生成密码、设置自定义密码时 token 作废。输错冷却仍只针对 `/auth`。密码关闭时，上传保持现在这样，不需要 token。

### 1.2 现状分析

`WiFiTransferServer.handleAuth` 核对密码，但 `handleUpload` 与 `beginStreamingUpload` 不看验证结果。浏览器每次上传都是新的 `NWConnection`，不能把「已登录」记在连接上。网页模板是 `wifi_transfer.html`，`uploadOne` 直接 `POST /upload`。

### 1.3 技术方案

新增可单测的 `WiFiTransferSession`：`passwordEnabled`、`issueUploadToken()`、`invalidateUploadToken()`、`allowsUpload(authorizationHeader:)`。密码关闭时放行；密码开启且 token 为空、缺少 `Bearer ` 前缀或与当前 token 不一致时拒绝。

`WiFiTransferServer` 用该会话替换单独的 `passwordEnabled` 字段。`/auth` 成功后把 token 放进 `{"success":true,"token":"..."}`。两条上传路径未通过时返回 401，不写文件。`stop`、`regeneratePassword`、`setCustomPassword`、`start` 都作废 token。

`wifi_transfer.html` 记住 token，上传时设置 `Authorization: Bearer`。收到 401 时清掉 token，隐藏上传区并重新显示密码框，避免密码作废后页面停在无法使用的上传区。

### 1.4 影响范围

只影响开启密码后的 WiFi 上传。不改端口、500MB 上限、multipart 解析方式。

### 1.5 测试要点

密码关闭无请求头也可上传；密码开启未签发、错误 token、无 Bearer 前缀均拒绝；签发后接受；作废后拒绝。

### 1.6 风险评估

旧网页缓存可能不带 token，上传会 401，需要重新打开页面并验证密码。这是预期行为。

## 需求 2：免费档 setTheme 拒绝高级主题

### 2.1 需求概述

`ThemeManager.setTheme` 在 `currentTier == .free` 且主题不是 `cloud_white` / `azure_sky` 时直接返回，不改当前主题，也不写偏好。付费墙仍由设置页弹出。`applyTier` 把免费档降回素云白简的路径保持不变。

### 2.2 现状分析

设置页在上锁后才调用 `setTheme`。`enforceThemeAccess` 通过 `setTheme(.cloudWhite)` 降级。现有 `P3FixTests` 在默认 Free 档直接 `setTheme` 高级主题，实现后要先 `applyTier(.premium)`。

### 2.3 技术方案

在 `setTheme` 开头用现有 `isPremiumTheme` 判断并返回。不改函数签名，不在 ThemeManager 里弹付费墙。

### 2.4 影响范围

设置页交互不变。启动时从偏好读出高级主题仍由 `init` 完成，随后 `applyTier(.free)` 降级。

### 2.5 测试要点

Free 调用暮光玫瑰或星际穹顶时 id 与 UserDefaults 不变。Free 仍可切到两套免费主题。Premium 可切高级主题。已有降级测试继续通过。

### 2.6 风险评估

若有代码在订阅状态就绪前调用 `setTheme` 切高级主题，会被拒绝。当前唯一外部调用在设置页，且发生在 `applyTier` 之后。
