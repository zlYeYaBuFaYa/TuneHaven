# 方案：WebDAV 并发下载（Review T7，含取消与同名两个关联中危项）

> 创建日期：2026-11-17 | 状态：已完成

## 1. 需求概述

`WebDAVService.downloadAndImport` 用同一个 `WebDAVClient`（actor）并发 3 个下载。`downloadFile` 只有一个 `downloadTask` 槽位，每次进入先 `downloadTask?.cancel()`；actor 在 `await task.value` 处可重入，后启动的下载会取消正在进行的那个，`defer { downloadTask = nil }` 还会清掉别人的任务引用。多选导入时大部分文件以「已取消」失败。

一并修复：

- **取消不生效**：`cancelDownload()` 置 `isCancelled`，下一个 `downloadFile` 进来就重置为 false；Service 的 `isCancelRequested` 无处读取，剩余文件照样下载并导入。
- **同名覆盖 / 半截文件**：临时文件为 `importTemp/{fileName}`，不同目录下的同名文件并发下载时写同一路径；失败时半截文件不删除。

不在范围：逐字节迭代 `AsyncBytes` 的性能问题（另行处理）。

验收标准：

1. 多选 N 个文件下载，互不取消，全部成功（服务器正常时）。
2. 点「取消」后：进行中的下载全部停止，不再派发新下载，不执行导入；未完成的任务标为失败「已取消」。
3. 取消后用同一连接再次下载可正常进行。
4. 不同目录下的同名文件分别下载、分别导入，内容不互相覆盖；导入使用原文件名。
5. 本次下载用到的临时文件（含失败的半截文件）在结束后全部删除。

## 2. 现状分析

| 文件 | 现状 |
|------|------|
| `Core/Network/WebDAVClient.swift` | `downloadTask` 单槽位、`isCancelled` actor 标志；`performDownload` 失败不删目标文件；`URLSession` 配置写死 `.default` |
| `Domain/Services/WebDAVService.swift` | TaskGroup 并发 3；目标路径 `tempDir/file.fileName`；下载后无论成功与否不检查取消；导入后只删成功下载的文件 |
| `Domain/Repositories/WebDAVClientProtocol.swift` | `downloadFile`、`cancelDownload()` 接口不变 |
| `Presentation/Import/WebDAV/WebDAVDownloadView.swift` | 「取消」调用 `webDAVService.cancelDownload()`，等待 `downloadAndImport` 返回后显示结果 |
| 测试 | 只有 XML 解析和模型测试；`SubscriptionGateTests` 已有 Stub client / factory / importer 的写法 |

## 3. 技术方案

### 3.1 WebDAVClient

- `downloadTask` 改为 `private var downloadTasks: [UUID: Task<URL, Error>] = [:]`；删除 `isCancelled`。
- `downloadFile`：

```swift
let id = UUID()
let task = Task { try await self.performDownload(...) }
downloadTasks[id] = task
defer { downloadTasks[id] = nil }
return try await withTaskCancellationHandler {
    try await task.value
} onCancel: {
    task.cancel()        // 调用方（TaskGroup）被取消时传递给内部 Task
}
```

- `cancelDownload()`：取消 `downloadTasks` 中全部任务（不清字典，由各自的 defer 移除）。
- `cleanup()`：同样取消全部任务后 `invalidateAndCancel`。
- `performDownload` 标为 `nonisolated`：它只用到 `config`、`session` 两个不可变成员，不需要 actor 隔离；否则 3 个下载的逐字节循环都在同一个 actor 上排队执行，并发形同串行。每次写入缓冲区时 `try Task.checkCancellation()`；任何错误（含取消）时删除目标文件再抛出。`URLSession.bytes` 本身也响应任务取消。`addAuth`、`Configuration` 相应标为 `nonisolated` / `Sendable`。
- 新增 `init(configuration:sessionConfiguration:)`，`sessionConfiguration` 默认 `.default`，测试注入带 `URLProtocol` 桩的配置；`timeoutIntervalForRequest` 仍取 `configuration.timeoutInterval`。

### 3.2 WebDAVService.downloadAndImport

- 本次临时根目录：`importTempURL/webdav-{UUID}/`；第 i 个文件放在 `.../{i}/{fileName}`。用序号子目录而不是改文件名，`importFromFiles` 以 `lastPathComponent` 作为导入文件名，保持原名。
- 派发前检查 `isCancelRequested`；为真则不再 `addTask`，并 `group.cancelAll()`。
- 结果处理：
  - `isCancelRequested` 为真：成功下载的任务保持 `.completed`，其余未完成的（`.downloading`/失败）标为 `.failed`，`error = "已取消"`；跳过导入；`errors` 追加「已取消」。
  - 否则按原逻辑：成功的进入 `importFromFiles`。
- 无论如何，结束时删除整个临时根目录（覆盖失败的半截文件与已取消的文件）。
- `cancelDownload()` 保持：置 `isCancelRequested = true` 并调用 `activeClient?.cancelDownload()`。

### 3.3 备选方案

- 每个下载新建一个 client：能避开槽位冲突，但 URLSession 与认证配置重复创建，且取消需要逐个跟踪，不采用。
- 临时文件名加 UUID 前缀：会把前缀带进入库文件名，不采用。

## 4. 影响范围

- 协议 `WebDAVClientProtocol` 不变，现有 Stub 不受影响。
- `WebDAVDownloadView` 不变：取消后 `downloadAndImport` 很快返回，结果页显示「已取消」与各任务状态。
- 无数据模型变更。

## 5. 测试要点

新增 `TuneHavenTests/WebDAVDownloadTests.swift`。

**WebDAVClient（真实 actor + URLProtocol 桩，无网络）**

1. 同一 client 并发 3 个下载（桩响应带少量延迟）：全部成功，文件内容正确。
2. 下载进行中调用 `cancelDownload()`：抛错，目标文件不存在。
3. 取消后再次下载：成功。
4. 服务器返回 404：抛错，目标文件不存在。

**WebDAVService（Stub client / importer，临时目录）**

5. 两个不同目录下的同名文件：下载到不同路径，导入收到的两个 URL 的 `lastPathComponent` 都是原文件名。
6. 下载期间调用 `cancelDownload()`：不调用导入；未完成任务为「已取消」；派发出的下载数少于总数。
7. 结束后本次临时根目录被删除（成功、失败两种情况）。

回归：全量 `TuneHavenTests`。

## 6. 风险评估

| 风险 | 应对 |
|------|------|
| `withTaskCancellationHandler` 的 onCancel 在任意线程执行 | 只调用 `Task.cancel()`，线程安全 |
| 取消发生在 `importFromFiles` 已开始之后 | 导入不中断（与修复前一致）；取消只影响下载阶段 |
| URLProtocol 桩与真实服务器差异 | 只验证并发与取消语义，与具体服务器无关 |
