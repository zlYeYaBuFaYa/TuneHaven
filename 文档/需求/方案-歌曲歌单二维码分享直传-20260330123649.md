# 方案：歌曲/歌单二维码分享直传

> 创建日期：2026-03-30 | 状态：已审核（Review 2 轮通过）

## 1. 需求概述

为 TuneHaven 新增**二维码分享直传**功能，用户选择要分享的歌曲或歌单后，应用启动局域网 HTTP 服务器并生成二维码；另一台设备上的 TuneHaven 扫描二维码后，通过同一 WiFi 局域网直接传输数据。

### 1.1 功能范围

| 操作对象 | 传输内容 | 操作粒度 |
|----------|---------|---------|
| 歌曲（音频+封面+歌词+元数据） | 局域网 HTTP 直传 | 单首 / 批量 |
| 自建歌单（结构+歌曲音频+封面+歌词） | 局域网 HTTP 直传 | 单个 / 批量 |

- 系统歌单（我喜欢/最近播放）不支持分享
- 不涉及 iCloud 或任何外部服务器
- 基础功能，不受订阅限制

### 1.2 核心规则

| 规则 | 描述 |
|------|------|
| 智能跳过 | 接收端已有的歌曲（标题+艺术家匹配）自动跳过不传输 |
| 歌单关联 | 歌单中接收端已有的歌曲直接关联本地歌曲，不重复传输 |
| 歌单分组 | 分享歌单时携带分组名称，接收端分组不存在则自动创建 |
| 同名歌单 | 接收端已有同名歌单时，以「歌单名-2」方式新建 |
| 附属资源 | 歌曲传输时一并传输封面和歌词文件 |
| 用户行为 | 不传输 playCount、isFavorite、lastPlayedDate 等 |
| 接收端展示 | 接收端在传输前、传输中、传输后均展示详细的跳过/关联/传输信息 |

### 1.3 入口

| 入口 | 位置 | 说明 |
|------|------|------|
| 主入口 | 设置 → 分享传输 | 含「发送」和「接收」两个选项 |
| 快捷入口 | 歌单详情页 → 工具栏 → 分享歌单 | 直接进入发送流程 |
| 快捷入口 | 歌曲列表 → 左滑菜单 → 分享 | 直接进入发送流程 |

### 3.2 详细实现

#### 3.2.1 分享类型扩展（`Domain/Entities/SyncTypes.swift` 追加）

```swift
// 分享会话信息
struct ShareSessionInfo: Codable {
    let deviceName: String
    let sessionToken: String
    let songCount: Int
    let playlistCount: Int
    let totalSize: Int64
}

// 分享歌曲摘要（用于接收端预览，不含文件路径）
struct ShareSongSummary: Codable, Identifiable {
    let index: Int
    let title: String
    let artist: String
    let album: String
    let duration: TimeInterval
    let fileSize: Int64
    let hasCover: Bool
    let hasLyrics: Bool

    var id: Int { index }
}

// 分享歌单摘要
struct SharePlaylistSummary: Codable, Identifiable {
    let index: Int
    let name: String
    let description: String?
    let groupName: String?
    let songCount: Int

    var id: Int { index }
}

// 接收端分析结果（展示给用户）
struct ShareAnalysis {
    let sessionInfo: ShareSessionInfo
    let songs: [ShareSongSummary]
    let playlists: [SharePlaylistSummary]
    let newSongs: [ShareSongSummary]
    let skippedSongs: [ShareSongSummary]        // 本地已有，将跳过
    let playlistLocalSongs: [String: Int]        // 歌单名 → 可关联的本地歌曲数
    let estimatedDownloadSize: Int64             // 实际需下载的大小（已跳过的不计）
}

// 分享传输结果
struct ShareTransferResult {
    let songsReceived: Int                       // 新接收的歌曲
    let songsSkipped: Int                        // 智能跳过的歌曲
    let playlistsCreated: Int                    // 创建的歌单
    let localSongsLinked: Int                    // 关联到歌单的本地已有歌曲
    let failedCount: Int                         // 失败数
}

// 分享进度（替代已移除的 SyncProgress/SyncPhase）
struct ShareProgress {
    let phase: SharePhase
    let current: Int
    let total: Int
    let currentFileName: String?

    var fractionCompleted: Double {
        guard total > 0 else { return 0 }
        return Double(current) / Double(total)
    }
}

enum SharePhase {
    case preparing
    case transferring
    case importing
    case completed
    case failed(String)
}
```

#### 3.2.2 分享服务协议（`Domain/Repositories/ShareServerProviding.swift`）

Domain 层定义分享服务器和客户端的抽象协议，Core 层提供实现，通过 DI 注入，遵循依赖反转原则。

```swift
// 分享服务器协议 — Domain 层定义
protocol ShareServerProviding: AnyObject {
    var isRunning: Bool { get }
    var serverAddress: String? { get }
    var qrCodeContent: String? { get }
    var connectedDevice: String? { get }

    var dataSource: ShareDataSource? { get set }

    func start() throws
    func stop()
}

// 分享数据源协议 — Domain 层定义，ShareService 实现
protocol ShareDataSource: AnyObject {
    func sessionInfo() -> ShareSessionInfo
    func songSummaries() -> [ShareSongSummary]
    func playlistSummaries() -> [SharePlaylistSummary]
    func audioFileURL(at index: Int) -> URL?
    func coverFileURL(at index: Int) -> URL?
    func lyricsFileURL(at index: Int) -> URL?
    func playlistSongs(at index: Int) -> [ShareSongSummary]
    func songExportData(at index: Int) -> SongExportData?
}

// 分享客户端协议 — Domain 层定义
protocol ShareClientProviding: AnyObject {
    func connect(to qrContent: String) async throws -> ShareSessionInfo
    func fetchSongList() async throws -> [ShareSongSummary]
    func fetchPlaylistList() async throws -> [SharePlaylistSummary]
    func fetchPlaylistSongs(at index: Int) async throws -> [ShareSongSummary]
    func fetchSongMeta(at index: Int) async throws -> SongExportData
    func downloadAudio(at index: Int, to dir: URL, progressHandler: @escaping (Double) -> Void) async throws -> URL
    func downloadCover(at index: Int, to dir: URL) async throws -> URL?
    func downloadLyrics(at index: Int, to dir: URL) async throws -> URL?
    func disconnect()
}
```

#### 3.2.3 分享服务器实现（`Core/Network/ShareServer.swift`）

```swift
@MainActor
final class ShareServer: ObservableObject, ShareServerProviding {
    @Published private(set) var isRunning = false
    @Published private(set) var serverAddress: String?
    @Published private(set) var connectedDevice: String?

    private var listener: NWListener?
    private var activeConnection: NWConnection?
    private let port: UInt16 = 8090
    private let sessionToken = UUID().uuidString

    var dataSource: ShareDataSource?

    func start() throws
    func stop()
    var qrCodeContent: String? { serverAddress.map { "\($0)?token=\(sessionToken)" } }
}
```

**HTTP API 端点**：

| 端点 | 方法 | 功能 | 响应 |
|------|------|------|------|
| `/api/share/info` | GET | 会话信息 | `ShareSessionInfo` JSON |
| `/api/share/songs` | GET | 歌曲摘要列表 | `[ShareSongSummary]` JSON |
| `/api/share/playlists` | GET | 歌单摘要列表 | `[SharePlaylistSummary]` JSON |
| `/api/share/playlist/{index}/songs` | GET | 歌单内歌曲列表 | `[ShareSongSummary]` JSON |
| `/api/share/song/{index}/audio` | GET | 下载音频文件 | 音频文件流 |
| `/api/share/song/{index}/cover` | GET | 下载封面文件 | 图片文件流 |
| `/api/share/song/{index}/lyrics` | GET | 下载歌词文件 | 文本文件流 |
| `/api/share/song/{index}/meta` | GET | 歌曲完整元数据 | `SongExportData` JSON |

**请求鉴权**：所有 API 请求须携带 `Authorization: Bearer {sessionToken}` header，token 不匹配返回 401。

**实现要点**：
- 参考 `WiFiTransferServer` 的 NWListener + 手写 HTTP 解析模式
- 文件下载使用流式响应（FileHandle 分块读取 + NWConnection 流式写入），避免大文件全量加载到内存
- 同时只允许一个客户端连接
- `connectedDevice` 在客户端首次请求 `/api/share/info` 时记录
- 所有端点通过 `dataSource` 协议获取数据，Core 层不直接引用 Domain 层类型的实现

#### 3.2.4 分享客户端实现（`Core/Network/ShareClient.swift`）

```swift
final class ShareClient: ShareClientProviding {
    private let session: URLSession
    private var baseURL: URL?
    private var token: String?

    init() {
        let config = URLSessionConfiguration.default
        config.timeoutIntervalForRequest = 30
        config.timeoutIntervalForResource = 300
        self.session = URLSession(configuration: config)
    }

    func connect(to qrContent: String) async throws -> ShareSessionInfo
    func fetchSongList() async throws -> [ShareSongSummary]
    func fetchPlaylistList() async throws -> [SharePlaylistSummary]
    func fetchPlaylistSongs(at index: Int) async throws -> [ShareSongSummary]
    func fetchSongMeta(at index: Int) async throws -> SongExportData
    func downloadAudio(at index: Int, to dir: URL, progressHandler: @escaping (Double) -> Void) async throws -> URL
    func downloadCover(at index: Int, to dir: URL) async throws -> URL?
    func downloadLyrics(at index: Int, to dir: URL) async throws -> URL?
    func disconnect()
}
```

**实现要点**：
- 解析 QR 码内容（格式 `http://ip:port?token=xxx`）提取 baseURL 和 token
- 所有请求添加 `Authorization: Bearer {token}` header
- 文件下载使用 `URLSession.download(for:)` 写入临时目录（`SandboxPathManager.syncExtractURL`）
- `downloadAudio` 通过 `URLSessionDownloadDelegate` 报告下载进度
- 连接失败时抛出明确错误（超时/网络不可达/鉴权失败）
- `ShareClient` 为普通类（非 actor），由 `@MainActor` 的 `ShareService` 持有，所有 async 方法在 URLSession 的后台队列执行

#### 3.2.5 分享服务（`Domain/Services/ShareService.swift`）

```swift
@MainActor
final class ShareService: ObservableObject {
    // MARK: - 发送端状态
    @Published private(set) var isSending = false
    @Published private(set) var sendProgress: ShareProgress?
    @Published private(set) var connectedReceiver: String?

    // MARK: - 接收端状态
    @Published private(set) var isReceiving = false
    @Published private(set) var receiveProgress: ShareProgress?
    @Published private(set) var analysis: ShareAnalysis?
    @Published private(set) var transferResult: ShareTransferResult?

    private let songRepo: SongRepository
    private let playlistService: PlaylistService
    private let groupService: PlaylistGroupService
    private let importService: ImportService
    private let fileStorage: FileStorageProviding
    private let serverFactory: () -> ShareServerProviding    // DI 注入工厂
    private let clientFactory: () -> ShareClientProviding    // DI 注入工厂

    private var server: ShareServerProviding?
    private var client: ShareClientProviding?
    private var sharedSongs: [Song] = []
    private var sharedPlaylists: [PlaylistDetail] = []
    private var songIndex: [String: [Song]] = [:]

    init(songRepo: SongRepository,
         playlistService: PlaylistService,
         groupService: PlaylistGroupService,
         importService: ImportService,
         fileStorage: FileStorageProviding,
         serverFactory: @escaping () -> ShareServerProviding,
         clientFactory: @escaping () -> ShareClientProviding)

    // MARK: - 发送端 API

    /// 准备分享歌曲，启动服务器，返回二维码内容
    func prepareSendSongs(_ songs: [Song]) async throws -> String

    /// 准备分享歌单，启动服务器，返回二维码内容
    func prepareSendPlaylists(_ playlists: [PlaylistDetail]) async throws -> String

    /// 停止发送
    func stopSending()

    // MARK: - 接收端 API

    /// 扫码连接并分析内容（返回预览信息）
    func connectAndAnalyze(qrContent: String) async throws -> ShareAnalysis

    /// 执行接收传输
    func executeReceive() async throws -> ShareTransferResult

    /// 取消接收
    func cancelReceive()
}
```

**依赖注入说明**：`ShareService` 通过协议（`ShareServerProviding` / `ShareClientProviding`）依赖服务器和客户端，不直接引用 Core 层具体类型。`serverFactory` 和 `clientFactory` 闭包由 `AppDIContainer` 在初始化时注入，返回 Core 层的 `ShareServer` / `ShareClient` 实例。

**发送端逻辑**：
1. `prepareSendSongs` / `prepareSendPlaylists` 被调用时：
   - 保存待分享的歌曲/歌单数据
   - 通过 `serverFactory()` 创建服务器实例，设置 `dataSource`（self 实现 `ShareDataSource` 协议）
   - 启动服务器，返回 `qrCodeContent` 供 UI 生成二维码
   - 监听 `server.connectedDevice` 更新 `connectedReceiver`

2. `ShareService` 实现 `ShareDataSource` 协议：
   - 遍历 `sharedSongs` 和 `sharedPlaylists`，对每个 index 提供对应的文件 URL
   - 音频文件路径通过 `SandboxPathManager.musicFileURL(relativePath:)` 获取
   - 封面路径通过 `song.coverImagePath` 获取
   - 歌词路径通过 `song.lyricsPath` 获取

**接收端逻辑**：

1. `connectAndAnalyze`：
   - 通过 `clientFactory()` 创建客户端实例，连接到发送端
   - 获取会话信息、歌曲列表、歌单列表
   - 构建本地歌曲索引（`title|artist` → `[Song]`）
   - 对比分析：哪些歌曲本地已有（跳过）、哪些需要下载
   - 对歌单内歌曲做同样分析：统计可关联的本地歌曲数
   - 计算实际需下载的大小
   - **检查本地磁盘剩余空间**，不足时提前告知用户
   - 生成 `ShareAnalysis` 返回给 UI

2. `executeReceive`：
   - 按分析结果，仅下载新歌曲（跳过已有的）
   - 每首歌下载 audio → cover → lyrics → 调用 `importService.processWiFiFile` 导入
   - 创建歌单并添加歌曲（已有歌曲直接关联本地 ID，新歌曲用导入后的 ID）
   - 处理歌单分组
   - 更新进度，生成 `ShareTransferResult`

**App 后台处理**：传输过程中 App 进入后台时，通过 `UIApplication.beginBackgroundTask` 申请后台执行时间（最长约 30 秒），确保小量传输可在后台完成。大量传输若后台时间耗尽，暂停传输并在 App 恢复前台后自动继续（已传输的文件保留）。

#### 3.2.6 歌曲匹配逻辑

在 `ShareService` 内部实现歌曲匹配（逻辑源自已移除的 `SyncImportService`，复用 `SongMatchResult` 枚举）：

```swift
// ShareService 内部
private func buildSongIndex() async {
    let allSongs = await songRepo.fetchAll(sortBy: .title, ascending: true)
    songIndex = Dictionary(grouping: allSongs) { "\($0.title)|\($0.artist)" }
}

private func matchSong(title: String, artist: String, album: String, duration: TimeInterval) -> SongMatchResult {
    let key = "\(title)|\(artist)"
    guard let candidates = songIndex[key] else { return .noMatch }

    if let exact = candidates.first(where: {
        $0.album == album && abs($0.duration - duration) < 2.0
    }) {
        return .exactMatch(exact)
    }

    if let fuzzy = candidates.first {
        return .fuzzyMatch(fuzzy)
    }

    return .noMatch
}
```

### 3.3 备选方案

#### 传输方案选择

| 方案 | 优缺点 |
|------|--------|
| **A. 独立 ShareServer（推荐）** | 与现有 WiFiTransferServer 解耦，互不影响；端口不冲突；逻辑清晰 |
| B. 扩展 WiFiTransferServer | 复用代码更多，但职责不单一；WiFiTransferServer 当前为 StateObject 非 DI，耦合度高 |
| C. Multipeer Connectivity | Apple 原生框架支持 WiFi+蓝牙自动发现；但 API 复杂、调试困难、不稳定 |

➜ 推荐 **A**：独立 `ShareServer`，保持职责单一，与现有 WiFi 传输完全解耦。

#### 扫码方案选择

| 方案 | 优缺点 |
|------|--------|
| **A. AVCaptureSession 自定义扫码（推荐）** | 完全控制 UI、无外部依赖、iOS 16.4+ 支持 |
| B. VNDetectBarcodesRequest（Vision） | 也可行，但面向图片而非实时视频流 |

➜ 推荐 **A**。

## 6. 风险评估

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| ShareServer 为新模块，HTTP 手写解析工作量 | 🟡 中 | 参考现有 WiFiTransferServer 模式，核心逻辑可复制 |
| 大文件流式传输内存管理 | 🟡 中 | 使用 FileHandle 分块读取 + NWConnection 流式写入 |
| AVCaptureSession 相机权限和兼容性 | 🟢 低 | iOS 16.4+ 稳定支持，权限处理有成熟模式 |
| 两端网络发现问题 | 🟢 低 | 二维码直接包含 IP+端口，无需 Bonjour 发现 |
| 与现有功能冲突 | 🟢 低 | 完全独立的新模块，不修改现有代码逻辑 |
| 端口冲突 | 🟢 低 | ShareServer 使用 8090，WiFiTransferServer 使用 8080 |

### 分期建议

| 期数 | 范围 | 优先级 |
|------|------|--------|
| **第一期** | 核心直传：ShareServer + ShareClient + ShareService + QRScannerView + ShareTransferView + ShareSendView + ShareReceiveView + 选择器 + 接收端信息展示 + 设置入口 | 高 |
| **第二期（可选）** | 快捷入口：歌单详情页分享按钮 + 歌曲左滑分享菜单 | 中 |
