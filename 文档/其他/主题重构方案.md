# TuneHaven 主题系统重构方案

> 版本：v1.2  
> 日期：2026-03-19  
> 状态：待确认  
> 分支：feat/theme-optimization

---

## 一、重构目标

| # | 目标 | 说明 |
|---|------|------|
| 1 | 移除颜色模式 | 删除 `ColorMode`（日间/夜间/跟随系统），每套主题自带固定 `ColorScheme` |
| 2 | 替换全部主题 | 删除现有 7 套旧主题，新增 6 套渐变色主题 |
| 3 | 通用接口设计 | 新增主题只需"定义色板 → 注册"，无需修改核心代码 |
| 4 | 保留壁纸功能 | `WallpaperManager` 自定义壁纸功能保持不变 |
| 5 | 背景动画延后 | 本次用 `LinearGradient` 占位，后续单独迭代 Canvas 动画 |

## 三、新架构设计

### 3.1 新增类型：GradientPair

元组不支持 `Hashable`/`Codable`，引入轻量结构体替代：

```swift
struct GradientPair: Equatable {
    let start: Color
    let end: Color
}
```

### 3.2 ThemeStyle（重构）

```swift
// ──── 重构前 ────
struct ThemeStyle: Identifiable {
    let id: String
    let displayName: String
    let previewColor: Color               // 移除
    let lightPalette: ThemeColorPalette   // 移除
    let darkPalette: ThemeColorPalette    // 移除
    // visualConfig 是 computed property（基于 id switch）
}

// ──── 重构后 ────
struct ThemeStyle: Identifiable, Equatable {
    let id: String
    let displayName: String
    let colorScheme: ColorScheme          // 新增：固定 .light 或 .dark
    let palette: ThemeColorPalette        // 简化：单色板
    let visualConfig: ThemeVisualConfig   // 改为 stored property
    let previewGradient: GradientPair     // 新增：设置页预览色

    static func == (lhs: ThemeStyle, rhs: ThemeStyle) -> Bool {
        lhs.id == rhs.id
    }
}
```

**变更说明**：
- `lightPalette` + `darkPalette` → 合并为单个 `palette`
- `previewColor: Color` → `previewGradient: GradientPair`（渐变预览更丰富）
- `visualConfig` 从 computed property（`ThemeVisualConfig.swift` 中基于 id 的 switch）改为 stored property（各主题扩展文件直接赋值），消除 switch 维护成本
- **属性名保持 `currentStyle`**（不做重命名，避免大范围无意义改动）

### 3.4 ThemeManager（大幅简化）

```swift
// ──── 重构前 ────
@MainActor
final class ThemeManager: ObservableObject {
    @Published private(set) var colorMode: ColorMode       // 移除
    @Published private(set) var currentStyle: ThemeStyle

    func setColorMode(_ mode: ColorMode)                   // 移除
    func resolvedPalette(for: ColorScheme) -> ...           // 移除
    var resolvedColorScheme: ColorScheme?                   // 移除
    private func effectiveColorScheme(system:) -> ...       // 移除
    private static let legacyThemeMapping: [...]            // 替换为新映射
}

// ──── 重构后 ────
@MainActor
final class ThemeManager: ObservableObject {
    @Published private(set) var currentStyle: ThemeStyle    // 属性名不变

    /// 直接返回当前主题色板
    var palette: ThemeColorPalette { currentStyle.palette }

    /// 当前主题要求的 colorScheme
    var colorScheme: ColorScheme { currentStyle.colorScheme }

    func setTheme(_ style: ThemeStyle)
    func applyToWindows()
    func refreshWindows()
    func scheduleWindowRefresh(delay:fullApply:)
}
```

**关键简化**：
- `applyToWindows()` 中 `colorMode.uiInterfaceStyle` → `currentStyle.colorScheme == .dark ? .dark : .light`
- `applyToWindows()` 中 `effectiveScheme == .dark ? darkPalette : lightPalette` → 直接用 `currentStyle.palette`
- `refreshWindows()` 同理简化
- `@AppStorage("color_mode")` 行删除
- `@AppStorage("theme_style")` 默认值从 `"meadow_breeze"` 改为 `"mint_breeze"`
- `legacyThemeMapping` 替换为新的 `legacyMapping`（见第六节）

### 3.5 ThemeColorPalette（不变）

22 个色彩属性完全保留，结构体零修改。`SemanticColor` 枚举也不变。

### 3.6 ThemeVisualConfig（更新枚举）

```swift
// ThemePatternType 旧值全部替换
enum ThemePatternType: String, Equatable {
    case mintLeaves        // 青云薄荷
    case oceanBubbles      // 深海鲸歌
    case cyberParticles    // 赛博霓虹
    case glacierCrystals   // 冰川幽蓝
    case auroraWaves       // 极光幻境
    case goldDust          // 夜幕鎏金
}

// ThemeVisualConfig 结构体不变
// 删除旧的 static 预设（comicPop, crimsonTech 等）
// 新增 6 个 static 预设（mintBreeze, deepOcean 等）
// 删除 ThemeStyle.visualConfig computed property（改为 stored property）
// hasCustomBackground computed property 保留不动
//   → 逻辑 `visualConfig.backgroundType != .solidColor` 对 6 套新主题均返回 true
//   → 若未来新增 solidColor 主题仍自动适配，无需改代码
```

### 3.7 ThemeBackgroundView（适配）

```swift
// codeGeneratedBackground 中的 switch 替换：
// 旧：case .comicSky: ComicPopBackground()
// 新：统一使用渐变色占位
private func codeGeneratedBackground(_ pattern: ThemePatternType) -> some View {
    LinearGradient(
        colors: [palette.gradientStart, palette.gradientEnd],
        startPoint: .top,
        endPoint: .bottom
    )
}
```

**行为变化**：旧架构中 `meadowBreeze` 的 `backgroundType` 是 `.solidColor`（无专属背景），其余 6 套是 `.codeGenerated`。新架构中 **6 套全部使用 `.codeGenerated`**，即 `hasCustomBackground` 始终为 `true`。这不影响功能——`ThemeBackgroundView` 在所有主题下都会显示渐变背景，与壁纸功能的叠加逻辑不变。

### 3.8 EnvironmentKey（微调 defaultValue）

```swift
struct ThemePaletteKey: EnvironmentKey {
    // 旧：static let defaultValue = ThemeStyle.meadowBreeze.lightPalette
    // 新：
    static let defaultValue = ThemeStyle.mintBreeze.palette
}
```

### 3.9 数据流对比

```
重构前:
  TuneHavenApp
    @State paletteScheme ← ColorMode + 系统外观
    themeManager.resolvedPalette(for: paletteScheme) → ThemeColorPalette
    .environment(\.themePalette, resolvedPalette)
    .preferredColorScheme(themeManager.resolvedColorScheme)
    .onChange(of: themeManager.colorMode) { refreshPaletteScheme() }

重构后:
  TuneHavenApp
    themeManager.palette → ThemeColorPalette（直接取，无计算）
    .environment(\.themePalette, themeManager.palette)
    .preferredColorScheme(themeManager.colorScheme)
    // 删除 paletteScheme、refreshPaletteScheme、colorMode onChange
```

### 3.10 扩展新主题的步骤（面向未来开发者）

```
步骤 1：新建 ThemeStyle+MyTheme.swift
   extension ThemeStyle {
       static let myTheme = ThemeStyle(
           id: "my_theme",
           displayName: "我的主题",
           colorScheme: .dark,
           palette: ThemeColorPalette(...22 个字段...),
           visualConfig: ThemeVisualConfig(
               backgroundType: .codeGenerated(.myPattern),
               cardStyle: .glassmorphism,
               fontStyle: .system,
               contentOverlayOpacity: 0.03,
               navigationBarBlur: true,
               tabBarBlur: true
           ),
           previewGradient: GradientPair(start: ..., end: ...)
       )
   }

步骤 2：ThemeRegistry.bootstrap() 中添加一行
   register(.myTheme)

步骤 3（可选）：新建专属背景 View
   ThemePatternType 中新增 case myPattern
   ThemeBackgroundView 中新增对应渐变/动画

完成。无需修改 ThemeManager、TuneHavenApp、SettingsAppearanceSection 等核心文件。
```

### 4.4 需要同步更新：Xcode 项目文件

删除 13 个文件、新增 6 个文件后，必须同步更新 `TuneHaven.xcodeproj/project.pbxproj`（或通过 Xcode 操作自动更新）。**遗漏此步会导致编译失败。**

### 4.5 不需要修改的文件（~35 个视图）

所有通过 `@Environment(\.themePalette)` 使用主题的视图**完全无需改动**：
- `EnvironmentKey` 名称不变（`themePalette`）
- `ThemeColorPalette` 结构体不变（22 个字段名不变）
- 注入方式不变（`.environment(\.themePalette, palette)`）

以下文件虽然使用 `@EnvironmentObject themeManager`，但只读取 `currentStyle.id` 或 `currentStyle.visualConfig`，**属性名未改变，无需修改**：
- `ThemeBackgroundView.swift` 中的 `themeManager.currentStyle.id` → 无需改（`currentStyle` 名未变）
- `ThemedCardModifier` 中的 `themeManager.currentStyle.visualConfig` → 无需改（`visualConfig` 改为 stored property 但访问方式一致）
- `ThemedFontModifier` 同理

## 八、测试更新

### 8.1 ThemeRegistry 测试隔离

`ThemeRegistry` 是单例，多个测试调用 `bootstrap()` 会累积主题。新增 `reset()` 方法：

```swift
// ThemeRegistry.swift 新增
func reset() {
    themes.removeAll()
}
```

测试中在 `setUp()` 调用 `ThemeRegistry.shared.reset()` 后再 `bootstrap()`。

### 8.2 测试用例清单

// ThemeTests.swift

func testAllThemesRegistered() {

## 十、风险与应对

| # | 风险 | 影响 | 应对策略 |
|---|------|------|---------|
| 1 | 旧用户升级后主题突变 | 体验中断 | `legacyMapping` 迁移到最接近的新主题 |
| 2 | `@Environment(\.themePalette)` 调用方是否受影响 | 35+ 个视图 | Key 名和 Palette 结构不变，**零改动** |
| 3 | 背景动画暂缺 | 视觉降级 | 渐变色占位已足够美观，后续迭代补充 |
| 4 | 启动闪白/闪黑 | 体验瑕疵 | 更新 LaunchBackground.colorset 匹配新默认主题 |
| 5 | ColorMode 残留引用 | 编译失败 | 删除 ColorMode.swift 后编译器会报错所有残留引用，逐个修复 |
| 6 | Xcode 项目文件不同步 | 编译失败 | Phase 4 中显式检查 .pbxproj |
| 7 | ThemeRegistry 单例测试污染 | 测试不稳定 | 新增 `reset()` 方法，每个测试前重置 |
| 8 | `hasCustomBackground` 全为 true | 行为变化 | 不影响功能，所有主题都显示渐变背景（含壁纸叠加） |
| 9 | Sheet/FullScreenCover 主题注入 | 弹窗颜色错误 | RootTabView 中的 palette 注入同步更新 |
