> 本文档聚焦系统技术设计：架构、导航系统、核心服务 API、主题系统、并发模型、关键流程、沙盒存储、性能策略与错误处理。项目目录结构与数据库 Schema 请参阅项目文档，产品需求请参阅需求文档。

## 一、整体架构

### 1.1 分层架构

Clean Architecture + MVVM，自顶向下五层：

```
App Layer        -- 应用入口(music_demoApp)、导航路由(AppRouter)、主题系统(ThemeManager)
Presentation     -- SwiftUI View + @ObservableObject Service（充当 ViewModel）
Domain           -- Entity、Service Protocol、Repository Protocol
Data             -- CoreData Repository 实现、Entity Mapper、AudioMetadataParser
Core             -- AudioEngine、Cache、Network、Persistence、Storage
```

依赖方向严格单向：上层可依赖下层，下层不得反向依赖。Domain 层通过 Repository Protocol 定义数据访问接口，Data 层提供 CoreData 实现。

### 1.2 Service 即 ViewModel

所有核心 Service 采用 `@MainActor final class: ObservableObject` 模式，Service 自身充当 ViewModel。View 通过 `@StateObject` 或 `@EnvironmentObject` 直接持有 Service，`@Published` 属性驱动视图刷新，`@MainActor` 保证属性读写在主线程完成。这避免了传统 MVVM 中 ViewModel 转发 Service 状态的胶水代码。

### 1.3 单例组件

| 组件 | 单例原因 | 注入方式 |
|------|---------|---------|
| AudioEngine | 全局唯一 AVPlayer，多实例会导致音频会话冲突 | @EnvironmentObject |
| PlaybackService | 播放状态全局共享（MiniPlayerBar + PlayerView 同步） | @EnvironmentObject |
| CoreDataStack | NSPersistentContainer 唯一，多实例导致数据不一致 | 直接引用 .shared |
| ImageCacheManager | 统一管理内存和磁盘缓存 | 直接引用 .shared |
| ErrorLogger | 全局日志收集，写入同一文件 | 直接引用 .shared |
| NowPlayingManager | 系统 Now Playing 信息中心唯一 | 直接引用 .shared |
| AudioSessionManager | AVAudioSession 全局唯一 | 直接引用 .shared |
| FileStorageService | 文件操作统一入口 | 直接引用 .shared |

AudioEngine 和 PlaybackService 的单例实例在 App 入口通过 `.environmentObject()` 注入 SwiftUI 环境，Presentation 层统一通过 `@EnvironmentObject` 获取，不直接引用 `.shared`。WallpaperManager 不再声明 `static let shared`，完全通过 `@EnvironmentObject` 注入。

### 1.4 依赖注入

启动时在 `music_demoApp` 中构建所有核心依赖，通过 `.environmentObject()` 注入 SwiftUI 环境：

```
@main music_demoApp
  -> MigrationManager -> CoreDataStack -> SandboxPathManager.createAllDirectories()
  -> 构建 Service 链: ThemeManager, MusicLibraryService, PlaylistService,
     ImportService, SearchService, AppRouter, SnackbarState, WallpaperManager,
     PlaybackService, AudioEngine, PlaylistGroupService
  -> 系统歌单初始化 -> loadSongs() -> cleanupOnLaunch()
```

RootTabView 的 `fullScreenCover`（PlayerView）和 `sheet`（各 SheetDestination）也完整传入所有 EnvironmentObject，确保弹窗上下文可访问全部服务。

## 二、导航系统

### 2.1 AppRouter

每个 Tab 拥有独立 NavigationPath，切换 Tab 时导航栈互不干扰：

```swift
@MainActor
final class AppRouter: ObservableObject {
    @Published var libraryPath  = NavigationPath()
    @Published var playlistPath = NavigationPath()
    @Published var settingsPath = NavigationPath()
    @Published var selectedTab: AppTab = .library       // .library | .playlist | .settings
    @Published var sheet: SheetDestination? = nil
    @Published var isPlayerPresented = false

    func navigate(to destination: AppDestination, in tab: AppTab? = nil)
    func popToRoot(in tab: AppTab? = nil)
    func present(_ sheet: SheetDestination)
    func dismissSheet()
    func openPlayer()     // spring(response: 0.5, dampingFraction: 0.86)
    func closePlayer()    // spring(response: 0.38, dampingFraction: 0.86)
}
```

### 2.2 RootTabView 布局

采用 `opacity + allowsHitTesting` 手动切换三个 Tab，而非标准 TabView（避免切换时视图销毁重建和 NavigationStack 状态丢失）：

```
RootTabView
 +-- ZStack (opacity + allowsHitTesting 切换)
 |   +-- Tab 0: NavigationStack(path: libraryPath)  + .safeAreaInset { MiniPlayerBar }
 |   +-- Tab 1: NavigationStack(path: playlistPath) + .safeAreaInset { MiniPlayerBar }
 |   +-- Tab 2: NavigationStack(path: settingsPath) + .safeAreaInset { MiniPlayerBar }
 +-- 自定义 TabBar（音乐库 / 歌单 / 设置）
 +-- ThemeBackgroundView（全局背景层）
 +-- .fullScreenCover { PlayerView }
 +-- .sheet(item: router.sheet) { SheetDestination -> View }
```

MiniPlayerBar 通过 `safeAreaInset(edge: .bottom)` 嵌入各 Tab 底部，全屏播放器以 `fullScreenCover` 呈现。

### 2.3 路由目标

**页面导航（Push）：**


## 三、核心服务 API

### 3.1 PlaybackService -- 播放控制

全局单例。依赖 AudioEngine、PlayQueueService、MusicLibraryService、CoreDataPlaylistRepository、CoreDataSongRepository。

**状态属性（@Published）：** currentSong: Song?, isPlaying: Bool, currentTime/duration: TimeInterval, playMode: PlayMode, playbackSpeed: Float, sleepTimerRemaining: TimeInterval?

**播放模式：**

| 模式 | 行为 |
|------|------|
| sequential | 顺序播放，末尾停止 |
| repeatOne | 单曲循环 |
| repeatAll | 列表循环 |
| shuffle | 加权随机，权重 = 1/(1+dislikeCount) |

**核心方法：**

```swift
func play(song: Song, in context: PlayContext) async   // 播放并按上下文构建队列
func prepare(song: Song, in context: PlayContext) async // 预加载不自动播放
func togglePlayPause()
func playNext()
func playPrevious()                                     // >3秒回到开头，否则上一首
func seek(to time: TimeInterval)
func skip(by seconds: TimeInterval)
func stop()
func cyclePlayMode()
func setSpeed(_ speed: Float)                           // 支持全局/单曲两种记忆
func setSleepTimer(minutes: Int?)
func toggleCurrentSongFavorite()
func dislikeAndSkip() async
```

**PlayContext：**

```swift
enum PlayContext {
    case allSongs(sortBy: SortField)
    case album(name: String, artist: String)
    case artist(name: String)
    case playlist(id: UUID)
    case queue                                          // 从已有队列播放，不重建
}
```

**速度记忆（UserDefaults speed_memory_mode）：** 模式 0 全局统一速度（存于 playback_speed），模式 1 单曲独立速度（存于 per_song_speeds 字典）。切歌时 `applySpeedForSong()` 根据模式加载对应速度。

**播放恢复：** 启动时从 UserDefaults `last_played_song_id` 恢复上次歌曲（仅加载不播放）。

### 3.2 PlayQueueService -- 播放队列

```swift

    func appendToQueue(_ songs: [Song]) -> QueueAddResult
    func insertNext(_ song: Song) -> QueueAddResult
    func removeFromQueue(at indices: IndexSet)
    func moveInQueue(from source: IndexSet, to destination: Int)
    func clearQueue()
    func nextSong(for mode: PlayMode, dislikes: [String: Int]) -> QueueItem?
    func previousSong() -> QueueItem?
    func saveQueueAsPlaylist(name: String, playlistService: PlaylistService) async throws -> Playlist
}
```

队列容量上限 `maxCount = 999`，超出返回 `.queueFull`。队列不持久化（`persist = false`），应用重启后清空。

## 四、音频引擎

### 4.1 AudioEngine

基于 AVPlayer 封装，全局单例，通过 `@EnvironmentObject` 注入 Presentation 层。

**状态机（PlaybackState，遵循 Equatable）：** idle -> loading -> playing/paused/error(Error)

**支持格式：** mp3, m4a, aac, alac, wav, flac, aiff, aif, caf

```swift
@MainActor
final class AudioEngine: ObservableObject {
    @Published var state: PlaybackState = .idle
    @Published var currentTime: TimeInterval = 0
    @Published var duration: TimeInterval = 0

    func load(url: URL) async       // 校验文件 -> 校验格式 -> AVURLAsset -> PlayerItem
    func play() / pause() / togglePlayPause()
    func seek(to: TimeInterval) / skip(by: TimeInterval)
    func stop()
    func cleanup()                   // 显式清理资源（停止播放 + 移除通知观察）
    func setSpeed(_ speed: Float)

    let playbackEndedSubject: PassthroughSubject<Void, Never>
    let timeUpdateSubject: PassthroughSubject<(currentTime: TimeInterval, duration: TimeInterval), Never>
}
```

事件通知使用 Combine `PassthroughSubject` 替代闭包回调，支持多订阅者且与项目整体 Combine 风格一致。单例不声明 `deinit`（永远不会触发），改为提供显式 `cleanup()` 方法。

**load 流程：** 验证文件存在 -> 校验扩展名白名单 -> AudioSessionManager.ensureActive() -> AVURLAsset.load(.isPlayable) -> 创建 AVPlayerItem + KVO 观察 -> replaceCurrentItem -> 添加 periodicTimeObserver（0.5s） -> 注册 playToEndTime 通知。

**AudioEngineError：** fileNotFound(URL), unsupportedFormat(String), assetNotPlayable(URL), loadFailed(underlying: Error)。捕获后 state 设为 `.error(Error)`。

### 4.2 音频中断处理

| 事件 | 处理 |
|------|------|
| 中断开始 | 自动暂停，记录中断前状态 |
| 中断结束 + shouldResume | 恢复播放并还原变速 |
| 路由变更（拔出耳机） | 自动暂停 |

### 4.3 NowPlayingManager

```swift
func update(song:currentTime:duration:speed:cover:)     // 切歌时全量更新
func updateElapsedTime(currentTime:duration:speed:)      // 进度变化时轻量更新
func setupRemoteCommands(onPlay:onPause:onNext:onPrevious:onSeek:)
```

远程命令映射：play/pause -> AudioEngine, nextTrack/previousTrack -> PlaybackService, changePlaybackPosition -> AudioEngine.seek。

## 六、并发模型

### 6.1 @MainActor 策略

所有 ObservableObject Service 标注 `@MainActor`：PlaybackService, MusicLibraryService, PlaylistService, PlayQueueService, ImportService, SearchService, PlaylistGroupService, WiFiTransferServer, AudioEngine。

Service 中需要执行耗时操作时，通过 `performBackground` 切到后台线程，完成后自动回到 `@MainActor` 上下文。

### 6.2 Core Data 双上下文

```swift
final class CoreDataStack {
    var viewContext: NSManagedObjectContext { container.viewContext }   // Main Queue, UI 绑定
    let backgroundContext: NSManagedObjectContext                       // Private Queue, init 时创建
    func performBackground<T>(_ block: @escaping (NSManagedObjectContext) throws -> T) async throws -> T
}
```

**performBackground 执行流程：**

```
1. backgroundContext.perform { block(backgroundContext) }    // Private Queue 执行写入
2. backgroundContext.save()                                  // 保存变更
3. 捕获 NSManagedObjectContextDidSave 通知
4. viewContext.performAndWait { mergeChanges(fromContextDidSave:) }  // 显式合并到主线程
5. viewContext.perform { continuation.resume }                // 主线程恢复调用方
异常: backgroundContext.rollback() 防止脏数据
```

两个上下文均使用 `NSMergeByPropertyObjectTrumpMergePolicy`（内存值优先）。viewContext 开启 `automaticallyMergesChangesFromParent` 作为兜底，performBackground 中的显式合并确保变更立即反映到 UI。

### 6.3 Combine + async/await 协作

Combine 用于响应式状态绑定，async/await 用于异步操作。sink 回调中通过 `Task { @MainActor in }` 桥接回主线程：

```swift
engine.$state.sink { [weak self] state in
    Task { @MainActor [weak self] in
        guard let self else { return }
        if case .playing = state { self.isPlaying = true }
    }
}.store(in: &cancellables)
```

### 6.4 线程安全要点

- Repository 所有写操作通过 `performBackground`，读操作在 viewContext 上
- FileManager 操作在后台线程，通过 async/await 返回
- NSCache 本身线程安全，ImageCacheManager 磁盘操作需后台执行
- UserDefaults 与 `@Published` 联动时需在主线程

## 七、关键业务流程

### 7.1 播放流程

```
用户点击歌曲 -> PlaybackService.play(song:in:)
  +-- 同一首歌正在播放 -> 返回
  +-- 同一首歌已暂停 -> engine.play()
  +-- 新歌曲:
      1. buildQueue(): 按 PlayContext 查询歌曲列表 -> replaceQueue()
      2. loadAndPlay():
         a. 保存 last_played_song_id
         b. 验证文件存在
         c. AudioSessionManager.ensureActive()
         d. AudioEngine.load(url:)
         e. applySpeedForSong()
         f. engine.play()
         g. libraryService.recordPlay()
         h. NowPlayingManager.update()
```

自动切歌：AudioEngine.playbackEndedSubject -> PlaybackService 通过 Combine .sink 订阅 -> PlayQueueService.nextSong(for:dislikes:) -> loadAndPlay()。

### 7.2 文件导入流程

```
用户选择文件 -> ImportService.importFiles(urls:)
逐文件 processFile():
  1. 校验扩展名（supportedExtensions 白名单）   -> 不支持: skippedUnsupportedFormat
  2. startAccessingSecurityScopedResource()
  3. 校验大小 <= 500MB                          -> 超限: skippedOversize
  4. SHA256 全文件哈希 -> 查重                   -> 重复: skippedDuplicate
  5. AudioMetadataParser 解析元数据（title/artist/album/duration/封面等）
  6. FileStorageService.copyToMusic() 复制到 Documents/Music/
  7. ThumbnailGenerator 生成多尺寸封面缩略图 -> Caches/CoverImages/
  8. 构建 Song -> CoreDataSongRepository.insert()
  -> 返回 ImportResult
```

### 7.3 软删除与撤销

```
用户删除 -> MusicLibraryService.softDelete(ids:)
  1. CoreData: softDeleted=true, deletedAt=now
  2. 文件移至 tmp/pending_delete/{uuid}/
  3. 构建 UndoToken -> Snackbar 30 秒倒计时
     +-- 撤销: softDeleted=false, 文件移回 Documents/Music/
     +-- 超时: 物理删除文件 + CoreData 记录 + 清除封面缓存
```

**UndoToken：**

```swift
struct UndoToken {
    struct MovedFile { let tempPath: String; let originalRelativePath: String }
    let songIds: [UUID]
    let movedFiles: [MovedFile]
    let expiresAt: Date
}
```

### 7.4 歌单管理

所有歌单写操作遵循统一模式：

```
PlaylistService -> performBackground { backgroundContext 写入 }
               -> save() + 显式 merge 到 viewContext
               -> loadPlaylists() -> @Published 更新 -> UI 刷新
```

### 7.5 睡眠定时

```
setSleepTimer(minutes:) -> 启动 1 秒间隔 Timer
  -> 每秒更新 @Published sleepTimerRemaining
  -> 归零: stop() + deactivate() + 可选本地通知
  -> 取消: setSleepTimer(minutes: nil)
```

## 八、沙盒与文件存储

### 8.1 目录规划

```swift
enum SandboxPathManager {

    static var playlistCoversURL: URL   // Caches/PlaylistCovers/
    static var pendingDeleteURL: URL    // tmp/pending_delete/
    static var wifiUploadURL: URL       // tmp/wifi_upload/
    static var importTempURL: URL       // tmp/import_temp/

    static func musicFileURL(relativePath:) -> URL
    static func coverImageURL(songId:size:) -> URL
    static func playlistCoverURL(playlistId:) -> URL
    static func createAllDirectories()  // 启动时统一创建
}
```

Song 实体的 `fileRelativePath` 存储相对于 Documents/Music/ 的路径，保证沙盒路径变化时不受影响。

## 九、性能策略

### 9.1 图片缓存（ImageCacheManager）

两级缓存：NSCache（内存）-> Caches/CoverImages/（磁盘）-> 从 ID3 标签提取（源）。

- **内存：** NSCache, totalCostLimit 50MB, 内存警告时清空
- **磁盘：** 默认 100MB、最大 300MB、LRU 淘汰（超限删最旧 20%）
- **上限控制：** UserDefaults `image_cache_limit_mb`

**缩略图尺寸：** small(100x100) 列表行, medium(200x200) 网格, large(400x400) 播放器, original(<=1024)。导入时 ThumbnailGenerator 一次性生成全部尺寸。

### 9.2 AVPlayer 优化

```swift
player.automaticallyWaitsToMinimizeStalling = false   // 本地文件无需缓冲，减少启动延迟
player.allowsExternalPlayback = false                  // 纯音频无需 AirPlay 视频
```

时间观察器 0.5 秒间隔，平衡进度条平滑度和 CPU 开销。NowPlayingManager.updateElapsedTime 仅修改进度字段，不重建整个 info 字典。

### 9.3 其他

- **文件去重：** 导入时 SHA256 全文件哈希，存入 Song.fileHash
- **Tab 切换：** opacity + allowsHitTesting 切换，三个 NavigationStack 始终存在，避免重建
- **CoreData 索引：** byArtist, byAlbum, byImportDate, byFileHash, bySoftDeleted
- **默认排除软删除：** 查询条件 softDeleted == false

### 10.2 ErrorLogger

全局日志单例，写入 Documents/Logs/error.log：

```swift
ErrorLogger.shared.log(.playbackFileNotFound(song.id), context: "PlaybackService.loadAndPlay")
// [2026-03-18T10:30:00+0800] [PLY001] PlaybackService.loadAndPlay - 文件不存在... at PlaybackService.swift:247
```

格式：`[ISO8601] [错误码] 上下文 - 描述 at 文件:行号`。轮转：5MB 上限，超限整体删除重建。

### 10.3 错误传播链路

```
Core/Data 层抛底层错误 -> Service 层捕获转为 AppError -> ErrorLogger.log() -> View 层展示本地化描述
```

AppLogger 提供非错误级别的结构化日志（调试/信息/警告），与 ErrorLogger 互补。

```swift
@MainActor
```

### 11.2 安全机制

- 可选 6 位数字密码（自动生成或自定义，UserDefaults wifi_password_enabled）

